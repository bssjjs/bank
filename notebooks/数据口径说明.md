# 数据口径说明

本文件记录建模前的全部口径处理决定。目的是让「为什么这样处理」有据可查，
而不是散落在几十行 pandas 代码里靠读代码反推。

对应代码：`src/bank/schema.py`（规则与常量）、`src/bank/dataset.py`（构建与自检）、
`src/bank/build.py`（入口）、`tests/test_schema.py`（单测）。

---

## 0. 一句话结论

原始数据**没有脏数据可洗**：45,211 行 × 17 列，0 缺失、0 空字符串、0 首尾空格、
0 大小写变体、0 重复行、0 特征重复但标签冲突、无越界值。需要做的是**口径处理**——
把三个语义陷阱（哨兵值 −1、未知类、通话时长泄漏）和一处结构缺陷（无年份）显式化。

| 产物 | 内容 |
|---|---|
| `data/model_dataset.parquet` | 45,211 行 × 29 列（原始 17 列未删 + 新增 12 列） |
| `data/feature_spec.json` | 特征清单（A/B 两版）、排除列及原因、有序映射、Pipeline 待办项 |
| `src/bank/schema.py` | 常量与纯函数，每条规则一个函数 |
| `tests/test_schema.py` | 14 项单测，覆盖边界值 |

---

## 1. 为什么把处理拆成两层

判断标准：**这条规则算出来的值，换一批数据会不会变？**

| 层 | 判据 | 落点 | 例子 |
|---|---|---|---|
| 口径层 | 不会变 | 一次性写入 parquet | `-1` 就是从未联系；「五月」就是第 5 月 |
| 变换层 | 会变 | sklearn `Pipeline` 内 fit 训练集 | 余额 1%/99% 裁剪阈值、标准化参数、类别表 |

分层的实际意义：口径层可以逐条审阅、写文档、做单测；变换层由 Pipeline 保证
只在训练集上拟合，测试集只 `transform`，不会信息回流。

## 2. 五条口径规则

### 2.1 哨兵值 `-1` → 派生三列，原列退出建模

`距上次联系天数 ∈ [−1, 871]`，其中 `−1` 表示**从未被联系过**，共 36,954 条（81.74%）。
直接入模会犯两个错：树模型把 `−1` 当作「最近联系过」（比 1 天前更近），
线性模型得到负天数。

| 新列 | 规则 | 类型 |
|---|---|---|
| `是否被联系过` | `pdays != -1` → 1/0 | int8 |
| `距上次联系天数_log` | 联系过：`log1p(pdays)`；未联系：`0.0` | float64 |
| `距上次联系天数档` | `0=未联系, 1=(0,30], 2=(30,90], 3=(90,180], 4=(180,365], 5=365+` | int8 有序 |

`_log` 取 0 不产生碰撞：天数 ≥ 1 时 `log1p ≥ 0.693`，所以 0 是「未联系」的唯一标记，
配合 `是否被联系过` 可无损还原原始信息。单测 `test_log_zero_only_for_never` 守着这条。

**为什么除了 log 还要分档**：认购率与天数不单调。

| 分档 | 条数 | 认购率 |
|---|---|---|
| 未联系 | 36,954 | 9.2% |
| 1~30 天 | 188 | 14.9% |
| 31~90 天 | 530 | **42.1%** |
| 91~180 天 | 2,480 | 27.4% |
| 181~365 天 | 4,416 | **17.8%** |
| 365 天以上 | 643 | 29.2% |

单靠一个 log 数值，线性模型无法表达「31~90 天最高、181~365 天反而最低」这个起伏。
分档边界 30/90/180/365 是业务阈值（月/季/半年/一年），不是分位数，属口径层。

### 2.2 「未知」保留为独立类别，不做填补

全表仅 3 列含 `未知`：联系方式 13,020（28.80%）、教育程度 1,857、职业 288。
它们是真实客群标签而非缺失值——`联系方式=未知` 的认购率 4.07%，是全表最低一档。

处理：不填补、不删除、独热编码时保留独立类别。新增派生列：

| 新列 | 规则 |
|---|---|
| `信息完整度` | `3 − (三列中等于"未知"的个数)`，取值 0~3 |

实测单调性（这是它值得保留的依据）：

| 信息完整度 | 条数 | 认购率 |
|---|---|---|
| 0 | 54 | 1.9% |
| 1 | 753 | 5.0% |
| 2 | 13,497 | 5.5% |
| 3 | 30,907 | **14.6%** |

### 2.3 教育程度：有序，但「未知」不占顺序位

认购率：小学 8.6% < 中学 10.6% < **未知 13.6%** < 高等教育 15.0%。
未知夹在中间，不是最低档，因此不能编码成 0。

- `教育程度序`：小学=1、中学=2、高等教育=3，未知留空（NaN）
- `教育程度_未知`：哑变量 0/1

唯一允许出现 NaN 的列就是 `教育程度序`（1,857 条），由 `SimpleImputer` 在 Pipeline 内填补。

### 2.4 通话时长：排除，但不删列

分档认购率单调：1 分钟内 0.2% → 1~3 分钟 3.9% → 3~5 分钟 10.9% → 5~10 分钟 19.2%
→ 10~16.7 分钟 44.0% → 16.7 分钟以上 59.7%。

它是通话**结束后**才知道的字段，线上打分时拿不到。处理：写入 `EXCLUDE_COLS`，
选列时显式剔除（`model_features()` 里有断言，误写进分组会直接报错）。
列本身留在数据集里，用于事后归因和下面的泄漏反证。

### 2.5 时间：月份有序化，切分方式必须跟着改

这张表**没有年份列**，只有 `联系月份`（中文）与 `联系日期`（1~31）。

| 项 | 处理 |
|---|---|
| 月份 | 中文 → 有序整数 1~12，另加 sin/cos 周期编码（十二月与一月相邻） |
| 日期 | 保留 1~31 数值 + sin/cos 周期编码（周期 31） |
| 切分 | **按时间切分**（见下方更正）：训练 `<2009-10-01`，验证 `≥2009-10-01`；不打乱、不分层 |

> **更正（2026-11-22）**：这里原先写「无法按时序切分 → 分层随机 70/15/15」，这个结论是错的。
> 行序本身就是时间序：按 `rowid` 看，30 个月块从 2008-05 连续走到 2010-11，月序只跨年回绕过两次，
> 块内日号从不回退；重建出 561 个日期（2008-05-05 → 2010-11-17）、全局单调，与 UCI「按日期排序」一致。
> 实现与断言见 `src/bank/timeaxis.py`、`tests/test_timeaxis.py`，证据与缺失月份表见 `docs/data_card.md` 第 4 节，
> 切分决策见 `docs/adr/0002-时间切分与建模窗口.md`。**随机切分会把同一时期的样本同时放进训练与验证，
> 验证集不再"像未来"，指标会虚高**——这条已列为 E5 对照实验（`docs/spec.md` 第 6 节）。

**月份是最危险的一列**。认购率：三月 52.0%（477 条）、十二月 46.7%（214 条）、
九月 46.5%（579 条）、十月 43.8%（738 条），而五月只有 6.7%（13,766 条）。
这种量级差异不可能来自客户属性，只能来自不同时期的宏观环境与营销活动。
模型若把月份当强特征，学到的是「那段时间发生了什么」，换年份即失效。

因此给出**双版本特征集**：

| 版本 | 列数 | 内容 | 用途 |
|---|---|---|---|
| A | 24 | 含 `月份序 / 月份_sin / 月份_cos` | 离线指标最优，回答「同期重跑能筛多准」 |
| B | 21 | 剔除上述三列，保留 `联系日期` 与日期周期编码 | 可上线，回答「明天来新客户能筛多准」 |

`联系日期` 保留在 B 版，因为「今天几号」在打分时是已知信息（月末效应可解释）。

**A−B 的差值就是时期红利**（单次分层切分 7:3，`SEED=42`，仅作口径验证，不是最终建模结果）：

| 特征集 | 逻辑回归 AUC | 随机森林 AUC |
|---|---|---|
| B 可上线 | 0.7525 | 0.7722 |
| A 含时间 | 0.7564 | **0.8023** |

随机森林上 A 版高 0.0301，逻辑回归只高 0.0039——说明月份的非线性交互主要被树模型吃掉了。
这个差值必须写进建模报告，只报 A 版数字会高估上线效果。

## 3. 变换层（不写进数据集，必须 Pipeline 内 fit）

| 项 | 规则 | 用在哪 |
|---|---|---|
| 分位裁剪 | 余额 `clip(1% 分位, 99% 分位)`，实测 −627 ~ 13,165 | 线性模型 |
| 幂次压缩 | `本次联系次数`(1~63)、`历史联系次数`(0~275) 先 `log1p` | 线性模型 |
| 标准化 | `StandardScaler` | 线性模型 |
| 缺失填补 | `SimpleImputer(strategy="median")`，只作用 `教育程度序` | 两者 |
| 类别编码 | `OneHotEncoder(handle_unknown="ignore")` | 两者 |
| 有序档位 | `距上次联系天数档`：树模型用整数，线性模型用 one-hot（不假设各档等差） | 按模型 |

树模型只做编码，不裁剪不标准化。

## 4. 泄漏反证实验（验收依据）

若剔除 `通话时长` 前后指标几乎不变，说明泄漏判断错了。实测（同一分层切分）：

| 特征集 | 逻辑回归 AUC | 随机森林 AUC |
|---|---|---|
| B 可上线 | 0.7525 | 0.7722 |
| B + 通话时长 | 0.8900 | **0.9065** |
| A 含时间 | 0.7564 | 0.8023 |
| A + 通话时长 | 0.8921 | 0.9330 |

随机森林 +0.1343、逻辑回归 +0.1375。差异如此集中在一列上，正是「结果泄漏」的特征：
它携带了结果本身的信息，而不是预测信息。复现：

```python
cols = D.model_features("B") + [S.DURATION]      # 加入泄漏列
# 其余同 §3 的 ColumnTransformer 组合，分层 7:3 切分，random_state=SEED
```

## 5. 已知例外（不修，但留档）

`距上次联系天数` 有值但 `上次营销结果=未知` 的共 5 条：

| 行号 | 年龄 | 职业 | 距上次联系天数 | 是否认购 |
|---|---|---|---|---|
| 40658 | 61 | 退休 | 98 | 是 |
| 41821 | 39 | 管理人员 | 168 | 否 |
| 42042 | 26 | 行政人员 | 188 | 是 |
| 43978 | 30 | 技术人员 | 416 | 否 |
| 45021 | 37 | 管理人员 | 528 | 否 |

两个字段口径不一致，占 0.01%。处置：**以 `距上次联系天数` 为准**，判定为
「有联系记录、结果未归档」，原值保留，不覆盖、不删除。理由是删了会凭空减少 5 条样本，
覆盖则要凭空捏造一个结果值，两者都比保留更差。

## 6. 怎么用

```python
import pandas as pd
from bank import dataset as D, schema as S

df = pd.read_parquet("data/model_dataset.parquet")
X, y = df[D.model_features("B")], df[S.TARGET]     # 上线口径
X_offline = df[D.model_features("A")]              # 离线口径
```

重建数据集（原始库只读，不会改动）：

```bash
python -m bank.build                 # 写 parquet + feature_spec.json
python -m unittest discover -s tests -v   # 14 项单测
```
