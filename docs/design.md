# 设计文档

> 口径细节在 `docs/problem.md` 与
> `docs/spec.md`，数据证据在 `docs/data_card.md`，指标数字在 `docs/model_card.md`。

## 1. 为什么做

银行电话营销团队每天的外呼名额由坐席数和工作时长决定，名单里只能打一部分人。名单本身
不排序，随机打会把大部分坐席时间花在几乎不会认购的人身上。我们要改变的不是“客户会不会
买”，而是“今天先打给谁”：把有限名额分配给当天分数最高的人。

这是一个**排序 + 名额分配**问题，不是“预测谁会买”的学术问题；模型分数只用来排序，不直接
当成客户概率去对外解释.

## 2. 做什么

**一句话定义**：在每次外呼之前，用当时系统里已有的客户属性与历史联系记录，预测本次被拨打
的客户在本次通话结束时会不会认购定期存款，再按每天的外呼名额决定今天先打给谁。

范围：

- 一行 = 一次联系尝试（数据没有客户 ID，不能按人聚合）。
- 输入只用通话发起前拿得到的信息；打完电话才知道的字段一律不进模型。
- 输出三个等级：`优先`（名额内）、`备选`（名额外的次优带）、`不建议`；服务返回分数、
  等级、主要因素和用途提示。
- 训练、评估、服务、模型包、解释、漂移监控是一条链，任何一环都不另写一套预处理。

## 3. 怎么做

1. **数据与口径**：只读 SQLite，按 `rowid` 重建时间轴；`configs/base.yaml` 放口径数字，
   `packages/core/src/bank/schema.py` 放列名、禁用列与常量，别处只引用。
2. **切分**：按时间切分，不打乱、不分层。训练 `< 2009-10-01`，验证 `≥ 2009-10-01`；
   缓冲 0 天是 ADR 0002 的决定，不是默认值。
3. **预处理与模型**：`Pipeline` 内完成缺失值、标准化、one-hot / 有序编码；训练与服务共用
   `packages/core/src/bank/features.py`，不另写一份。主模型是逻辑回归 + 特征集 B（21 列，
   去掉月份三列），选择依据见 ADR 0005。
4. **决策**：名额 = 验证集行数 × 10% = **356 人**；切点是验证集上真实存在的分数分位数
   （`method="higher"`，不插值、不四舍五入）：`优先 ≥ 0.57298`、`备选 ≥ 0.253228`。
   阈值存原始 float，发布时复核“按切点选中的人数必须等于名额”（ADR 0023）。
5. **交付**：`model_bundle.v1`（特征、决策、指标、运行时版本）、FastAPI 服务、单条解释、
   PSI 漂移与告警、标签回流；模型包与原始数据都不进 Git。
6. **质量门**：`scripts/ci.py` 五道门（ruff check、ruff format --check、mypy、
   lint-imports、pytest + 覆盖率），末行必须打印“质量门：全绿”。

## 4. 做到什么程度

### 4.1 四口径

| 口径 | 取值 | 说明 |
| --- | --- | --- |
| 样本 | 原始 45,211 行 × 17 列；建模窗口 2008-11-01 ~ 2010-11-17 共 21,093 行 | 一行 = 一次联系尝试；窗口外与缺月份段不进建模 |
| 标签 | `是否认购 = 是` 为 1；全表 5,289 正例（11.70%） | 缺失/其它取值报错，不静默当负例 |
| 时点与切分 | 标签在通话结束时产生（窗口 0 天）；训练 `< 2009-10-01`（17,537 行 / 2,327 正例 / 13.27%），验证 `≥ 2009-10-01`（3,556 行 / 1,782 正例 / 50.11%） | 按时间切分，不打乱、不分层；验证集只报数，不回头调参 |
| 决策 | 名额 356 人；`优先` / `备选` / `不建议` 三档 | 名额是业务外生约束，不是模型学出来的阈值；0.5 阈值只作对照 |

### 4.2 主指标与基线

**主指标：AP（PR-AUC）**。理由：名额只有 356 人，业务关心的是“把正例尽量排在前面”，
而不是在 50% 基率上把所有人分类正确；AP 对排序整体敏感，且不像 ROC-AUC 那样在基率变化时
虚高。名额内精确率/召回率作为业务读数一起报，不单独当主指标。

| 对象 | AP | 名额内精确率 | 名额内召回率 | Brier |
| --- | --- | --- | --- | --- |
| 随机排序（参考） | ≈ 0.5011（等于验证集基率） | ≈ 0.5011 | ≈ 0.1998（356/1,782） | — |
| 规则打分基线 | 0.6412 | 0.7640 | 0.1526 | 0.4924 |
| **逻辑回归 + 特征集 B（主模型）** | **0.6498** | **0.7416** | **0.1481** | **0.2852** |

主模型在 356 个名额里打中 264 人；AP 比规则基线高 0.0086，但 95% 区间
`[0.6286, 0.6777]` 与规则基线重叠——**不能声称模型显著优于规则**。选它的理由是概率可校准
（Brier 0.2852 对 0.4924）与单条可解释，不是“分数更高”。

### 4.3 验收线

- 名额内精确率目标 75%，实测 **74.16%**（264/356），差 0.84pp；目标不调低，按未达记录。
- 名额内召回率目标 30% 与名额 356 不相容：356/1,782 的上限是 **19.98%**，30% 在数学上
  不可能。该行是早期文档笔误，已改为只报告实测 **14.81%**，不把不可达的数当门槛。
- AP 高于两条基线中较好者（0.6498 > 0.6412），达标；ROC-AUC 0.6438 与 Brier 0.2852
  只报告，不设门槛（时期漂移下 Brier 天然偏低，见模型卡）。
- 发布门禁另有一套更低的硬线（AP ≥ 0.50、名额内精确率 ≥ 0.60、特征数 ≥ 10），
  与上面的研究目标分开，见 `docs/adr/0006-模型包与发布.md`。

### 4.4 验证集与“测试集只用一次”

本项目**没有另切封存测试集**：验证集只有 3,556 行，再切一段会让名额内精确率的 95% 区间
宽到没有判断力（ADR 0013 记录了取舍）。因此验证集同时承担“定决策规则”和“报最终数字”，
所有指标都注明是验证集、3,556 人、名额 356 人；这是明确限制，不冒充独立测试集。

## 6. 明确不做（至少三条）

1. **不把 `通话时长` 放进特征**：它是通话结束后才知道的结果，单变量 AUC 0.8076，属于泄漏；
   `EXCLUDE_COLS` 有断言守着。要做泄漏对照只能显式加列、单独跑，不改 `model_features()`。
2. **不把 `距上次联系天数` 原列当数值入模**：`-1` 是“从未联系”的哨兵，不是天数；只用派生
   三列（是否被联系过 / `_log` / `_档`）。
3. **不把“未知”填补、删除或当缺失**：`联系方式=未知` 占 28.80%，是真实类别，且认购率最低；
   当成缺失会掩盖这一档的业务问题。
4. **不做因果/增量结论**：只做排序，不回答“打了比不打好多少”；数据没有真正的对照组。
5. **不做客户级去重与跨人建模**：没有客户 ID，强行去重只能靠特征组合猜，会把误差带进来。
6. **不用验证集调参、选模型、定名额**：调参只在训练期内的内层时间窗（`tune.py`），
   验证集只报数；报任何指标都写清集合、人数、名额人数。
