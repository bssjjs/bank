## 一、v0 的四个病灶（我们同形态，要提前堵）

1. **大文件会进 Git**：`.gitignore` 只挡 `__pycache__/.venv/build/dist/*.egg-info`，结果 `notebooks/model.pkl`（103 MB）、`train.parquet`/`valid.parquet`、`top15.csv`、`data/incident.db`（18 MB）全都能被 `git add` 收进去。
2. **自动选列把泄漏列选进来了**：`notebooks/feature_cols.json` 25 列里有 `known_diabetes`（已确诊 = 标签泄漏）、`chronic_mgmt_tag`（纳管标签）、`district/education/income_level`（敏感与分组元数据）。教训：**列清单不能由数据自动生成，必须人定 + 机器守**。`bank` 的等价物是 `通话时长`。
3. **训练和服务是两套代码**：`notebooks/predict.py` 里 `joblib.load("model.pkl")` 用相对路径；`df["bmi"] = weight/(height/100)**2` 在服务侧重算一遍；`df.reindex(columns=feature_cols)` 把缺列留空、交给 `SimpleImputer` 悄悄补。→ 正好是 `bank` M3/M4/M5 要避免的三件事：派生必须进 Pipeline、bundle 必须存列顺序与类型、缺列必须拒绝而不是悄悄填。
4. **没有说明和验收**：README 0 字节、无 docs、无 tests、无质量门、无 AGENTS.md。

## 二、risk 可直接搬的机制

### 1. 仓库与依赖方向

- 一个仓库三个包 + uv workspace + 全仓一个 `uv.lock`；根 `pyproject.toml` 只当 workspace 根（`[tool.uv] package = false`、`default-groups = ["dev"]`、`[tool.uv.workspace] members`、`[tool.uv.sources]` 指向 workspace）。
- 发行名 ≠ 导入名：`drisk-core`→`diabetes_risk`、`drisk-training`→`drisk_training`、`drisk-api`→`drisk_api`。理由写在 `docs/adr/0001`、`0002`：看一行 import 就知道属于哪个包，分层契约按导入名写。
- **两道防线**：`.importlinter` 两条契约（core 用 `forbidden` 不许依赖 training/api；training 与 api 用 `independence` 互不依赖）+ `tests/architecture/test_dependencies.py` 补 import-linter 看不见的：契约被删了 lint 照样绿、pyproject 里只声明不 import（服务一部署就把训练的 sklearn/mlflow 全带上）。

### 2. 质量门 `scripts/ci.py`

- 五道门、便宜在前、失败即停：`ruff check` → `ruff format --check` → `mypy` → `lint-imports --no-logo` → `pytest --cov`。
- 门是**数据**不是一串 if：`class Gate(NamedTuple): name; command`；`gates() -> list[Gate]` 可被测试直接读。
- `ROOT = Path(__file__).resolve().parent.parent`，不依赖"当前在哪个目录"；工具一律用 `sys.executable` 跑（用 uv.lock 锁的版本，不用系统里碰巧那个）；`lint-imports` 没有 `-m` 入口，按 `Path(sys.executable).parent` 找 `.exe`。
- 子进程 `env PYTHONUTF8=1`（中文 Windows 默认 GBK，配置文件是 UTF-8）。
- 覆盖率门槛只从 `pyproject.toml` 的 `[tool.coverage.report] fail_under` 读，`ci.py` 不写死。
- 最后一行固定 `质量门：全绿` / `质量门：未通过`；全绿判定必须 `len(results) == len(planned) and all(...)`（`all([])` 是 `True` 的坑）。

### 3. 守门测试（防止"为了让门变绿而改规则"）

- `test_quality_gate.py`：断言**真正执行的命令**（`commands[0][1:] == ["-m","ruff","check","."]`），不断言给人看的显示名；断言门槛等于 pyproject 里的数。
- `test_rules.py`：`COVERAGE_FLOOR = 85`、`REQUIRED_RUFF_RULES = {"E","F","W","I","B","UP"}` 只许更严不许更松；正则扫全仓禁止 `sys.path` 改动与 `os.chdir`（注释也算，宁可误报）；禁止 pytest `pythonpath`。
- `test_layout.py`：uv workspace 成员必须正好三个；每个包是 src 布局且有 `__init__.py` + `py.typed`；包确实从本仓库装进环境（比对 `__file__` 与 `importlib.metadata.version`）；导入名互不相同；不建 `.github/`；`CLAUDE.md` 首行必须是 `@AGENTS.md`（规矩只有一份）。

### 4. 基线冻结 `baselines/` + `scripts/freeze_baseline.py`

- 目录里每个文件算 SHA256 写 `SHA256SUMS`，`--write` 冻结、`--check` 校验；**基线一经冻结只读**，后面拿实现对账，绝不反过来改基线。
- 跨机器同字节的三个细节：`sorted(...)` 定行序、`relative_to(...).as_posix()` 用正斜杠、`write_text(..., newline="\n")` 写 LF。
- `check()` 把"缺文件 / 多文件 / 内容被改"三类分开报，不只说"不一致"。
- `test_baselines.py`：对每个基线目录跑同一套 check；再在 `tmp_path` 里造一份"冻结 → 改动 → 被发现"，证明链条是通的。

### 5. 步骤回放 `scripts/replay_steps.py`

- 对每个 `step-*` tag：`git worktree add --detach <tmp>/<tag> <tag>` → 在 worktree 里 `uv run python scripts/ci.py` → `git worktree remove --force`；剥掉外层 `VIRTUAL_ENV` 避免 uv 误判。
- 证明"任意一步都能独立成立"——正好对应 `bank` 任务书"四个 tag 每个都要能跑"。

### 6. 文档三件套

- `docs/steps/A*.md`：只有"目标 / 验收 / 不做"三行。
- `docs/cards/*.md` 模块卡七节：一句话目标、谁会用它（调用示例）、公开接口逐字带签名、必须成立的规则 + 为什么、不做、审查项（考卷查不了、人看 diff 时逐条看）、验收命令与期望结果。
- `docs/devlog/YYYY-MM-DD.md`：状态（分支、每个 tag 对应 commit、最新质量门）、今天完成、今天修掉的关键问题、常用命令、环境注意、明天建议、改动清单。

### 7. 配置：`configs/base.yaml` + `extends`

- 全部默认值在 `base.yaml`；实验配置用 `extends` 只写差异，字典深合并、列表整体替换；`config_hash` 按**合并、校验之后**的内容算。
- 每段 pydantic `extra="forbid"`（拼错键立刻报错）+ `frozen=True`（加载后不可改）；跨段关系用 `model_validator(mode="after")` 校验（`train_end < valid_start <= valid_end <= data.as_of`）。
- 派生量用 `@property` 算，不写进 YAML：`maturity_days = window_days + max_report_lag_days`，避免两处数字对不上。

### 8. 特征目录 `configs/features.yaml`

- 三段：`fields`（`name / group / range / required / display_name / categories`）、`forbidden`、`derived`。
- `CatalogSpec` 强制：分组顺序 `numeric → binary → categorical` 单调前进（允许缺组、不许回退）；`fields` 至少一条；输入/派生/禁用三组不许撞名；**`REQUIRED_FORBIDDEN` 写在 core**（`visit_id/resident_id/visit_date/label`），任何入口绕不过。
- `_UniqueKeyLoader`：同一层重复键直接报错，不静默取最后一个。
- `catalog_hash = sha256_json(spec.model_dump())`：注释、缩进、键序都不影响；改一个中文名就变。
- 类别值统一加引号（YAML 会把裸写 `yes/no/on/off` 读成布尔）。

### 9. 指纹工具 `packages/core/.../repro.py`（可直接搬）

- `sha256_file(path, chunk_size=1<<20)`：分块喂 digest，大文件不爆内存，结果与一次读完相同。
- `canonical_json(obj)`：`sort_keys=True, ensure_ascii=False, separators=(",", ":")`；`Path` → `as_posix()`，`date/datetime` → `isoformat()`，**其他类型抛 `TypeError` 而不是 `str(obj)`**（`str()` 可能带内存地址，每次不一样）；统一 UTF-8 编码再算字节指纹。
- `sha256_json(obj)`、`git_sha(root)`、`git_dirty(root)`（失败返回 `None` 表示"不知道"，不让程序崩）。

### 10. 流程纪律

- 每步先是 `docs/steps/` 里的三行说明，人确认后才写代码；每步一个 tag；`AGENTS.md` 第六节只追加**已完成步**的规则。
- `tests/exam/` 是"人写考卷、agent 实现"的验收；仓库外还有 mutants 脚本跑错误实现，验证考卷抓得住错误。→ 五人组可以让每个人给别人的模块写验收测试，作为 M9 的加分项。

## 三、落到 `bank` 上的待办与取舍

- 顺序：M1 文档四件套 → M2（抽样、`rowid` 与日期重建、标签、时间切分 + 缓冲、两表、内容指纹、`FROZEN.json`、manifest、清洗台账）→ M8（三包、`configs/features.yaml`、配置强校验、注册表、`ci.py`、pytest 迁移）→ M3 → M4–M7 → M9。
- `bank` 的 `configs/features.yaml` 建议**直接用中文列名作 `name`**：原始 17 列就是中文、业务方是银行、能省掉中英映射层；代价是 API 契约、PSI 报告、前端表单都用中文键。这条要写成 ADR 再定。
- `通话时长` 必须进 `forbidden`，并且由 core 侧强制校验（照 `REQUIRED_FORBIDDEN` 的做法），不能只在训练侧检查。
- `pdays`（`距上次联系天数`）的 -1 哨兵已由现有 `src/bank/schema.py` 派生成三列；`features.yaml` 里应把原列列进 `forbidden`。
- `ci.py` 五道门可照搬，但**覆盖率门槛不要照抄 85**：任务书只要求 ≥10 个测试，先不启用 `fail_under` 或设一个低门槛，等测试补上来再收紧。
- `data/frozen/FROZEN.json` + 校验脚本照 `freeze_baseline.py` 的做法（sorted、as_posix、LF、三类问题分开报）。
- 环境注意：DSH 沙箱下 pytest `tmp_path`、uv 缓存可能因 Windows ACL 不可写；用 `.venv\Scripts\python.exe` 直接跑可绕开。
