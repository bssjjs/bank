## 三、提交怎么切

历史是按模块 + 讲义步提交的（`M0`→`M8`→`M1`→`M2`→`M3`→`M4`→`M5`→`M7`→`M9`，再往后是讲义对照步 C-L1a…F7）。任务书要求「每人都有提交」，做法是：**每个人从自己负责的模块里挑一个完整可验证的子步骤，自己写一遍并提交**（不是拆别人的提交，也不是只改个错别字——要能独立过质量门），例如：

| 角色 | 建议补的提交（都能独立过门） |
| --- | --- |
| 架构与质量 | `M8: 给 ci.py 加一道门 + 守门测试`、`M9: 给某个模块补一张模块卡并接进 architecture.md` |
| 数据 | `M1: 给 profile 加一张按月正例率表并更新数据卡`、`M2: 加一条清洗规则（带命中行数与测试）` |
| 模型与评估 | `M3: 加一个新指标到 metric_specs 与报告`、`M3: 补一组切片维度` |
| 发布与服务 | `M5: 给某个字段补一条 422 用例与文档`、`M7: 调 watch 的关注线并记录理由` |
| 前端 | `M6: 实现页面（表单由 /v1/model 生成）`（实现后再提交） |

提交前自查：`git status --short` 干净状态开始；改完跑 `scripts\ci.py` 全绿；提交信息写清「做了什么、为什么」，中文。
