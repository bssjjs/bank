## 二、每个人都要能做到的三件事

1. 从零把演示线八步跑通（见 `README.md`「现在能跑什么」第 2–10 步）。
2. 说清自己模块的数字从哪条命令来（每个数字都有出处，见 `AGENTS.md` 第二节）。
3. 说清自己模块「没做什么、为什么」（见 `docs/architecture.md` §7.2 与对应模块卡）。

## 三、提交怎么切

现在的历史是按模块提交的（`M0`→`M8`→`M1`→`M2`→`M3`→`M4`→`M5`→`M7`→`M9`）。任务书要求「每人都有提交」，建议按下面切分：每个人从自己负责的模块里挑一个**完整可验证**的子步骤重做提交（不是拆别人的提交，而是各自补上自己那一段的实现与文档），例如：

| 角色 | 建议补的提交 |
| --- | --- |
| 架构与质量 | `M8: 特征目录与 schema 对账`、`M9: 架构文档与模块卡` |
| 数据 | `M1: 时间轴重建与画像`、`M2: 清洗台账与冻结` |
| 模型与评估 | `M3: 规则基线与主模型评估` |
| 发布与服务 | `M4: 模型包契约`、`M5: 服务契约与 422`、`M7: PSI 漂移报告` |
| 前端 | `M6: 动态表单与结果卡`（实现后再提交） |

## 四、当前仓库事实

- 分支 `main`，提交记录可用 `git log --oneline` 查看；里程碑 tag：`m1-topic`、`m2-design`、`m3-mvp`、`final`（`git tag -n` 看说明）。
- 测试与质量门：`.venv\Scripts\python.exe scripts\ci.py` 末行「质量门：全绿」。
- 数据与模型包不进 Git：`data/frozen/` 进 Git，`data/processed/`、`models/`、`mlflow.db` 不进；换机器后按 README 重跑即可复现全部数字。
