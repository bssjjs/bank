## 二、三个 AI 出错实例

### 案例 1：README 的数字与基线对不上

- **当时的任务**：补 README 的验收说明，把服务错误码和主模型指标写清楚。
- **AI 的输出**：README 里把字段级错误码 `422` 写成了 `424`，主模型「名额内精确率」也与 `baselines/` 里的快照对不上。
- **怎么发现的**：拿 README 的数字逐项对 `baselines/v1/` 与 `docs/model_card.md`，两处对不上。
- **纠正**：提交 `ac12e05 docs: 修正 README 两处笔误（422 写成 424、主模型名额内精确率与 baselines 对不上）`。
- **复核**：`git show ac12e05 -- README.md`。

### 案例 2：把「联系方式」误记成隐私列

- **当时的任务**：梳理字段清单，标出可能要脱敏的列。
- **AI 的输出**：在文档里写下「`联系方式` 待移除」，把它当成了电话号码一类的个人信息。
- **怎么发现的**：负责人指出这一列存的是联系渠道类型（手机 / 固话 / 未知），不是号码；`docs/data_card.md` 也写着 13,020 行是「未知」。
- **纠正**：先提交 `9a72fe9` 记下待办，随后用 `4fd3050 docs: 更正为联系方式不是隐私列（联系渠道类型，非手机号）` 撤回该结论；特征清单与 15 个必填输入保持不变。
- **复核**：`git show 9a72fe9` 与 `git show 4fd3050`。

### 案例 3：NaN 让 422 自己炸成 500

- **当时的任务**：给 `/v1/predict` 加字段级校验，保证坏输入返回 422 而不是 500。
- **AI 的输出**：数值字段只校验了类型与范围，没有挡住 `NaN`/`Inf`；请求进来后模型侧抛异常，接口返回 500。
- **怎么发现的**：服务测试里构造 `NaN` 请求，期望 422，实际拿到 500。
- **纠正**：提交 `eeabfa5 fix(服务): 数值字段关掉 inf/NaN，422 只回 loc/msg/type（NaN 曾让返回 422 自己炸成 500）`，并在 `tests/service/test_api.py` 留下回归用例。
- **复核**：`git show eeabfa5`；`uv run python -m pytest tests/service/test_api.py -q`。
