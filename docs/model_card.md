# 模型卡：电话营销认购倾向（逻辑回归 B 集）

- 版本：模型 `m3-1.1.0`；模型包 `models/serving/1.1.0` 为 production（`1.0.0` 降为 staging）
- 模型包血统：`bundle.json` 的 `runtime` 记 python 3.12.16 / sklearn 1.9.1 / pandas 3.1.1 / numpy 2.5.5；sklearn 主次版本或 Python 主版本不一致时拒绝加载（ADR 0020）
- 训练日期：2026-11-22
- 训练来源：`python -m bank_training.train`；mlflow 实验 `bank-marketing`，主模型 run `60741fa06a4049c49942bb12fc9fe88a`
- 模型包 run：`python -m bank_training.export --version 1.1.0 --promote` → run `7530c4281634419fa243470de1be3305`
- 数据集指纹：`train.parquet` 内容指纹 `03832a96…`、`valid.parquet` `d680004e…`（见 `data/frozen/FROZEN.json`）
- 代码位置：`packages/training/src/bank_training/`（Pipeline、指标、解释、实验）

## 1. 用途

给定一通电话**开始之前**就知道的客户信息（年龄、职业、账户余额、上次营销结果等 21 个特征），给出「这个人在本次通话中认购定期存款」的概率，再按每天的外呼名额从高到低排序，决定先打给谁。

**不适用于**：判断客户是否值得长期维护；给非本行客户打分；把分数当「认购可能性百分比」对外宣传（见第 5 节校准）；对 2008-05~2008-10 那段数据分布外推。

## 2. 训练与验证数据

| 项目 | 训练集 | 验证集 |
| --- | --- | --- |
| 时间范围 | 2008-11-04 ~ 2009-09-30 | 2009-10-01 ~ 2010-11-17 |
| 行数 | 17,537 | 3,556 |
| 正例（认购） | 2,327（13.27%） | 1,782（50.11%） |
| 特征数 | 21（特征集 B） | 同左 |

切分按时间、不打乱、不分层（ADR 0002）；缓冲 0 天——标签在通话结束即得，不存在「未来才发生的标签」。两个正例率相差 13%→50% 是真实的时期漂移，不是切分错误。

## 3. 输入与处理

- 特征清单来自 `configs/features.yaml`（33 个字段里 21 个可入模），代码只读目录，不硬编码列名。
- **禁用列**：`通话时长`（打完电话才知道，单变量 AUC 0.8076）、`距上次联系天数` 原列（−1 是「从未联系」的哨兵，另用派生三列）、`是否认购`（标签本身）、`序号/年份/月份序_重建/重建日期/label`（切分与排序用）。
- 处理全在 Pipeline 内，训练与服务共用：类别列 one-hot（未知类别不报错、填 0）；有序列按 YAML 的类别顺序编码；数值列中位数填补 + 标准化；「未知」当类别，不填补。
- 派生列（是否被联系过、距上次联系天数 log 与分档、信息完整度、教育程度序、月份与日期的周期编码）由 `bank.dataset.build_dataset` 生成，服务端拿原始 17 列调同一个函数。

## 4. 指标（验证集 3,556 人，名额 356 人 = 10%）

| 指标 | 数值 | 口径 |
| --- | --- | --- |
| AP（average precision） | 0.6498 | 全验证集排序质量 |
| ROC-AUC | 0.6438 | 全验证集 |
| 名额内精确率 | 0.7416 | 取前 356 人，其中 264 人认购 |
| 名额内召回率 | 0.1481 | 264 / 1,782 |
| Lift@356 | 1.4798 | 精确率 / 基率 0.5011 |
| Brier | 0.2852 | 概率校准，见第 5 节 |
| 阈值 0.5 对照 | 选中 574 人，精确 0.7596、召回 0.2447 | 只作对照，不是上线口径 |
| 名额内 F1 / 准确率 | 0.2470 / 0.5472 | 与上面同一个混淆矩阵（tp 264 / fp 92 / fn 1518） |
| 对数损失 / ECE | 0.8080 / 0.2292 | 校准口径，只报告不设门槛 |

**95% 区间**（200 次按行重抽，名额随行缩放，种子 42；两个口径的差异见评估报告）：
名额内精确率 `[0.7051, 0.7838]`、召回率 `[0.1403, 0.1561]`、AP `[0.6286, 0.6777]`、
ROC-AUC `[0.6262, 0.6654]`、Brier `[0.2750, 0.2938]`。区间只说明这 3,556 人的抖动幅度，
不是上线效果的保证——跨期漂移比区间大一个量级。

完整表在 `reports/evaluation_report.md` 与同名的 `.json`（每次训练重算，并记进主模型的 mlflow run）。

对照物（同一验证集、同一名额）：规则打分 AP 0.6412 / 名额内精确 0.7640 / Brier 0.4924；随机森林+特征集 A AP 0.6229 / 0.7500；逻辑回归+特征集 A AP 0.5959 / 0.6180。

局限：名额内精确率 74.2%，比 `docs/problem.md` 定的 75% 低 0.8 个百分点——目标没改，如实记在这里；规则基线的 76.4% 达标，但概率质量不可用。取舍见 ADR 0005。

## 4b. 决策规则（名额制，A 口径）

- 名额 = 验证集行数 × `configs/base.yaml` 的 `quota.frac`（0.10）= 356 人；策略名与次优带宽度在 `configs/decision.yaml`，强校验（ADR 0023）。
- 切点是**验证集上真实存在的分数分位数**（`method="higher"`，不插值、不四舍五入）：`优先 ≥ 0.57298`（正好 356 人）、`备选 ≥ 0.253228`（再覆盖到 40% 分位，共 1,422 人）、其余不建议。
- 发布时复核：按切点选中的人数与名额差超过 1 人，`export.py` 直接拒绝发布（`_gate` 第 5 条）。
- 阈值不是概率：训练期正例率 13%、验证期 50%，0.57 不代表 57% 的认购概率。

## 5. 校准与漂移（必须读）

- 模型平均分 0.272，验证集实际基率 0.501：概率**系统性偏低**，因为训练期正例率只有 13%，而验证期是 50%。这是分布漂移，不是 bug。
- 因此**不要**用 0.5 阈值做决定，也不要把分数当真实概率对外解释；上线只用「按分数排序取前 N 人」。
- **不允许**用验证集做 Platt/Isotonic 校准：那是拿验证集调参，违反 ADR 0002 的规矩。要校准就等 PSI 告警后在线上数据上单独做，并留档。
- 监控：M7 对「线上」批次算 PSI（分箱边界用训练集分位数固定），至少盯 `上次营销结果`、`联系方式`、`账户余额` 三个特征。
- 可靠性表（验证集，10 箱）：平均分 0.2719、基率 0.5011；ECE 0.2292、Brier 0.2852；最偏的一箱是 `[0.1, 0.2)`，平均分与实际正例率差 0.2837。完整十箱表在 `data/processed/evaluation_report.md` 的「校准」一节，由 `python -m bank_training.train` 现场生成。

## 5b. 切片：模型对谁不够好（验证集，名额按切片人数比例分配）

名额 356 人分到各切片时按人数比例缩放，少于 100 人的切片不报。以下是 2009-10 以后验证集上的实测：

| 切片 | 最好的一档 | 最差的一档 |
| --- | --- | --- |
| 职业 | 蓝领工人 0.8800（25 人名额）、学生 0.8621 | 行政人员 0.6383（47 人名额） |
| 教育程度 | 高等教育 0.7609 | 小学 0.6905 |
| 联系方式 | 固话 0.7750 | **未知 0.1200**（25 人名额只打中 3 人） |
| 婚姻状态 | 未婚 0.7752 | 已婚 0.7306 |
| 年龄档 | 30-39 岁 0.8246 | 18-29 岁 0.7313 |

读法：`联系方式=未知` 这一档的 AP 只有 0.1468、名额内精确率 0.1200，说明**这群人基本靠分数排不出来**（该档基率只有 12.65%，模型给的低分方向是对的，但档内区分度几乎没有）。运营上应该把这一档从「按模型排序外呼」里拿出来单独处理，不要让它占满名额。完整五张表见 `evaluation_report.md` 的「切片」一节。

## 6. 解释

单条解释由 `bank.explain.explain_one` 给出：逻辑回归的贡献 = 系数 × 标准化后的取值，取绝对值前 5 项，正数推高分数、负数压低。

示例（验证集上分数 0.8505 的一位客户，实际认购）：

| 特征 | 取值 | 贡献 |
| --- | --- | --- |
| 账户余额 | 81,204 | +1.395 |
| 上次营销结果=成功 | 成功 | +1.118 |
| 联系方式=固话 | 固话 | −0.602 |
| 职业=退休 | 退休 | +0.555 |
| 住房贷款 | 否 | +0.454 |

这套贡献与线性 SHAP 等价（零额外依赖）；换成树模型时必须同步改 `_column_names` 的断言，否则会静默错位。

**全局解释**（`python -m bank_training.global_explain`，训练时也会随主模型 run 一起产出）：把「模型靠什么排序」落到整张表，两套重要度并列——线性贡献重要度（各行 |系数 × 标准化值| 的平均，与单条解释同源、等价线性 SHAP）与置换重要度（打乱该列后 AP 的下降量，模型无关参照）。产物为 `data/processed/global_explain.md`（表 + 结论）与 `global_explain_beeswarm.png`（蜂群图）。实测 `上次营销结果` 的置换重要度 0.1556，远高于第二名的 0.0035，说明模型主要靠「上次是否成功」这一条排序，与规则基线的最高权重一致。

## 7. 已知限制

1. 无客户 ID：不能按人分组切分，同一客户的历史通话可能同时出现在训练与验证两侧；影响方向是**高估**泛化能力。
2. 数据只覆盖 2008-05~2010-11、单一葡萄牙零售银行，迁移到别的机构必须先重训。
3. 2008-09 整月缺失、2008-10 只有 80 行：时间轴有洞，月份块不是连续的 30 个。
4. 训练期正例率 13%、验证期 50%：模型对「热期」的排序能力弱于对「冷期」。
5. 规则基线在名额内精确率上不落下风：现模型的价值在排序细分与校准，不在多打中几个人。
