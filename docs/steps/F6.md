# F6：告警与定时检查

> 步骤卡。对应 tag `step-F6`，命令 `python -m bank_training.watch`。

## 目标

让「变差了」这件事有人知道：一轮检查读漂移报告、回流汇总与服务指标，按配置的阈值分级，
投递到终端 / JSONL / webhook；同一特征连续两轮越线才建议重训。

## 验收

- `uv run python -m bank_training.watch` 打印每条告警（`[alert] drift/psi_联系月份: ...`），
  末行「检查完成：info 0 / warn 5 / alert 7」，写出 `data/processed/watch.json`（契约 `watch_report.v1`）。
- 连跑第二次，多出一条 `[alert] retrain/psi_two_runs: ...`，退出码 1。
- `--base-url http://127.0.0.1:8000` 能读 `/metrics`；服务没起时只多一条 `service/service_unreachable` 的 warn，不崩。
- `configs/watch.yaml` 写错键或把告警线设到关注线下面，直接报错并指出哪一项。
- `pytest tests/unit/test_watch.py -q` 17 项全过。

## 不做

- 不做常驻守护进程（`--interval` 只用于演示）；调度交给外部 cron / 任务计划程序。
- 不自动重训、不自动改 `configs/model.yaml`：条件到了只报警，命令留给人跑。
- 不在告警里写客户特征值（只写特征名、PSI、比例）。
- 不接 Prometheus（服务指标走 `/metrics` 的 JSON，见 ADR 0015）。
