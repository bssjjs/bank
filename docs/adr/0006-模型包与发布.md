# ADR 0006：模型包、校验和与发布回退

- 状态：已采纳（M4）
- 日期：2026-11-22

## 背景

M3 的训练脚本每次都在内存里现训一个模型，服务端拿不到「训练时到底用了哪些列、按什么规则判等级」。
参考项目 diabetes-v0 的教训是：`model.pkl` 扔在 notebook 目录里、`feature_cols.json` 与代码各记一份、
服务端 `joblib.load("model.pkl")` 用相对路径，换台机器就崩，没人说得清线上跑的是哪次训练。

任务书 M4 要求模型包至少六项、统一加载、缺列拒绝、不覆盖旧版本，另外「发布门禁」与「版本状态机与回退」可以只设计。
本 ADR 决定：六项与统一加载做成真的，门禁做成真检查，回退做成改一行指针。

## 决策

### 一、一个版本一个目录，绝不覆盖

```
models/serving/
├── current.json          {"version": "1.0.0"}
├── 1.0.0/
│   ├── bundle.json       契约、特征顺序、决策规则、指标、训练来源、校验和
│   └── model.joblib      预处理器 + 分类器（sklearn Pipeline）
└── 1.0.1/               下一次导出，与 1.0.0 并存
```

- 版本号 `x.y.z`，由导出命令手工给（`python -m bank_training.export --version 1.0.1`）。
- 目标目录已存在直接报错，不覆盖：旧版本是回退时要用的，覆盖等于把回退路拆了。
- 写入先落在同级的 `.staging-<版本>` 临时目录，自检通过后原子改名；中途失败不会留下半个包，
  也不会占住版本号（第一次实现就踩过：`mkdir` 之后 `joblib.dump` 失败，留下半个目录，重跑报「已存在」）。

### 二、`bundle.json` 的六项契约

| 项 | 字段 | 为什么必须有 |
| --- | --- | --- |
| 模型本体 | `model_file: {name, sha256, size}` | 知道加载的是哪个文件，大小与哈希都能对账 |
| 输入列顺序与类型 | `features: [{name, type, order}]`（21 列，order 从 1 连续） | 服务端按这个顺序喂列，顺序错了 sklearn 不报错、分数会错 |
| 决策规则 | `decision: {mode, quota_frac, quota_n, level_cutoffs, threshold, explain_top_k}` | 名额制是主口径；等级切点冻结在这里，单条请求才能判「优先/备选/不建议」 |
| 训练来源 | `training: {run_id, experiment, data_fingerprint_train/valid, config_fingerprint, git_sha, trained_at, rows_train/valid, n_features}` | 任何一次预测都能倒查到 mlflow 的哪次 run、哪份冻结集 |
| 指标快照 | `metrics: {ap, roc_auc, precision_at_quota, recall_at_quota, brier, ...}` | 报告数字与包内数字同源，不用回跑 |
| 校验和 | `checksum: {algorithm: "sha256", value}` | 文件被改过就拒绝加载 |

另外三项服务于前端：`inputs`（**15 个**必填原始输入列，带中文名、单位、范围、类别）、`required_columns`
（与 `inputs` 同顺序，服务端用它拒绝缺列请求）、`catalog_fingerprint`（这份字段说明出自哪一版 `configs/features.yaml`）。

`inputs` 与 `features` 不是一回事：`features` 是模型真正吃的 21 列（含 `距上次联系天数_log` 这类派生列），
`inputs` 是前端要用户填的 15 个原始列。前端不许知道派生规则，派生只在服务端做一次。

**为什么是 15 而不是 14（这条口径改过一次，改的理由更要写下来）**：最初按"非派生且非禁用"筛，
把 `距上次联系天数` 也筛掉了。但模型的特征集里有它的三个派生列（`是否被联系过` / `_log` / `_档`），
`derive_features` 必须要原始列才能算——服务端第一次拿真实请求跑就报
`KeyError: 缺少原始列：['距上次联系天数']`。所以规则改成"非派生，且不是**绝不外露**的两列"
（`SERVING_EXCLUDED = (通话时长, 是否认购)`）：`forbidden` 约束的是"能不能原样喂给模型"，
不是"能不能出现在表单上"。`通话时长` 是打电话之后才知道的，用户根本填不出来；`是否认购` 是标签。
其余禁用列（`序号`/`年份`/`重建日期` 等）都是派生或切分用的，本来就不在 `inputs` 里。

### 三、校验和怎么算

`checksum.value = sha256(canonical_json(bundle.json 去掉 checksum 字段))`，
规范化用的是 `repro.canonical_json`：键排序、中文不转义、`separators=(",", ":")`、日期 ISO、Path 用 `/`。
模型文件另有 `sha256_file`（1 MiB 分块）。加载时三查：JSON 校验和、模型文件大小、模型文件哈希。

## 发布门禁

`bank_training/export.py` 里的 `_gate()`：特征数 ≥ 10、验证集 AP ≥ 0.50、名额内精确率 ≥ 0.60、ROC-AUC > 0.5，
任何一条不过就不写包。这些阈值不是拍脑袋：规则基线 AP 0.6412、名额内精确率 0.7640，主模型必须站在这条线附近，
低于它说明这次训练出了问题（数据换错、特征漏了、预处理反了）。

门禁只挡「明显坏了」的包，不挡「比线上差一点」的包——后者属于发布判断，记在 ADR 里由人决定。

## 回退

回退 = 把 `current.json` 改回旧版本：`B.write_current("1.0.0")`。
不删目录、不改包内文件，所以回退后还能再切回新版本。`write_current` 会先检查目标版本确实有 `bundle.json`。

## 否掉的方案

- **把模型存成 `model.pkl` 放仓库根**（v0 的做法）：没有版本、没有校验和、没有列顺序，服务端靠猜。
- **覆盖同名版本**：省一个版本号，代价是回退无路可走。
- **`current.json` 里存全量元数据**：指针就该只有一行，元数据在版本目录里，改指针不会引入不一致。
- **等级用概率阈值（如 0.5/0.7）**：验证集基率 50%、主模型平均分 0.27，概率本身系统性偏低（ADR 0005），
  阈值会让「优先」一个人都选不出来。改用验证集分数分位数：优先 = 名额前 1/3（356/3 ≈ 118 人），备选 = 第 356 名。
- **让 `bank_api` 直接 import `bank_training` 复用打分**：会打破 `.importlinter` 的独立性契约，
  而且服务端会被迫带上 mlflow/joblib 训练依赖。所以推理路径（`features.py`、`explain.py`）搬到 core，
  训练与 api 都调它，两边同一条代码路径。

## 后果

- `models/` 不进 Git（`.gitignore` 已挡），模型包不是交付物，是「现场用一条命令造出来的产物」；演示前必须重跑 export。
- `bank_api` 只依赖 `bank`，它的打分与导出时用的打分是同一个函数，不存在「训练一套、上线另一套」。
- 加一次发布就是多一个版本目录 + 改一行指针，答辩时演示回退只要改指针。
- 版本号手工递增，忘了就报「已存在」——这是有意的，宁可报错也不静默覆盖。
