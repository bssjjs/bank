# ADR 0010：对账点 1 —— 从原始库重算，与冻结账单逐项比

- 状态：已采纳（2026-11-24）
- 相关：`packages/core/src/bank/reconcile.py`、`tests/unit/test_reconcile.py`、ADR 0003（内容指纹与冻结）

## 背景

任务书要求「一条命令从原始数据生成训练集/验证集并打印行数、正例数、内容指纹，重跑指纹不变」。我们已经有 `bank.freeze` 和它的 `--check`，但 `--check` 比的是「今天重跑同一套代码得到的产物」和「冻结时的产物」——两者用的是同一条代码路径，同一个构建器，同一个 `build()`。也就是说，如果 `build()` 本身错了（比如少过滤一个窗口、标签算反），`--check` 会稳定地通过，因为它比的是自己。

课程讲义第二轮卷一把这件事写成「对账点 1」，并且要求三件事：

1. 重算的来源是**原始库**，不是冻结的 parquet；
2. 比对的对象是**账单**（`manifest.json` 里记下的事实），逐项比，不是「一个总指纹相等」；
3. **能失败**：账单一改，退出码必须是 1，且不得回写冻结数据。

这三条恰好补上 `--check` 的盲区：`--check` 回答「口径有没有漂、库有没有被换」，`reconcile` 回答「账单和重建结果对不对得上」。

## 决定

新增 `python -m bank.reconcile`：

- 只读 `data/bank-marketing.db`（`raw.py` 的只读连接）与 `configs/base.yaml`，调用 `freeze.build()` 在内存里重算，**不读 `train.parquet` / `valid.parquet`**。
- 对账项 22 项：源文件 sha256（manifest 与 FROZEN 各一份）、源文件存在性、配置 sha256（两份）、特征目录与配置特征集一致、原始行数/正例/列清单、窗口行数/正例/日期范围、训练与验证的行数/正例/内容指纹/日期范围、名额、特征数。
- 输出逐项 `[一致]` / `[不一致]`；有不一致就打印差在哪并退出 1；一致时打印「对账通过：从原始库重建的两表与冻结账单逐项一致」。
- **不写任何文件**：`data/frozen/` 的内容在运行前后 sha256 不变（有测试守）。

配套测试（`tests/unit/test_reconcile.py`，7 项）：

- 真实数据对账退出 0；
- 对账前后 `FROZEN.json` 的 sha256 不变；
- 对账项覆盖讲义点名的十个检查点；
- 把账单抄到临时目录后改坏三处（训练行数 +1、验证内容指纹改成 0、FROZEN 里的源文件指纹改成 f），退出码都必须是 1；
- 账单缺失时退出 1。

## 否掉的选项

| 选项 | 为什么不 |
| --- | --- |
| 只保留 `freeze --check`，不单独做对账 | 它和构建器是同一双眼睛，构建器的错它看不见；讲义的核心就是「独立于被检验对象」 |
| 对账比 parquet 文件字节 | 字节随 pyarrow 版本变，换台机器就报假警；比内容指纹（规范化 CSV 的 sha256），跨机器一致（ADR 0003） |
| 对账时重新写一遍 `data/frozen` 再比 | 对账一旦写盘，就把「检查」变成了「覆盖」，改坏的数据会被悄悄接受；对账必须只读 |
| 把对账做成 `freeze` 的一个子命令 | 两者语义相反（一个写、一个只读），命令行分开，演示时一句话能说清 |
| 对账参数写死在代码里 | 项目只有一个冻结目录，但测试要能指向临时账单；用 `--frozen-dir` 与函数参数留口 |

## 后果

- 演示线在第 ① 步之后多一条命令，答辩可以现场把账单改坏一次，让人看着它红——比「我跑过两次指纹一样」有说服力。
- 新增 7 项单测，总数 224 → 231；`scripts/ci.py` 会自动跑到。
- 对账耗时约 3–4 秒（要重切一遍数据），可以接受。
- 它和 `--check` 并存，职责写进 AGENTS 第二节，避免以后有人把两者合并。
