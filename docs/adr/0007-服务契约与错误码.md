# ADR 0007：服务契约与错误码

- 日期：2026-11-22
- 状态：已采纳（M5）
- 相关：ADR 0006（模型包与发布）、`packages/api/src/bank_api/`、`configs/api.yaml`

## 1. 背景

任务书 M5 要求：`/health` 与 `/ready`、`POST /v1/predict` 按契约④返回分数/等级/主要因素、
越界值返回 422 并**指出是哪个字段**、`GET /v1/model` 提供版本/指标/字段说明让前端动态生成表单、
每条预测落一行记录、服务只读模型包且**不导入训练代码**；批量接口与 503/500 属于"必须设计"。

难点不是写 FastAPI，而是**同一份字段口径要同时约束四个人**：数据（`configs/features.yaml`）、
训练（模型包 `inputs`/`features`）、服务（422 的字段与范围）、前端（表单的控件与枚举）。
任何一处手抄，就会漂移。

## 2. 决定

### 2.1 请求体由模型包生成，不手写

`build_input_model(bundle)` 在启动时读 `bundle.json` 的 15 个 `inputs`，用
`pydantic.create_model` 造出 `PredictInput`：数值列带 `ge`/`le`，类别列带内联 `enum`。
于是 `/docs` 里看到的范围就是模型包里的范围，改字段只有一条路径：改 `features.yaml` → 重导出包。

类别字段用运行时拼出来的 `Literal[tuple(categories)]`，不用 `Enum`：`Enum` 会在
`/docs` 里多一个 component，名字取类名，中文会被 pydantic 改写成 `__`（实测
`components.schemas` 里出现 `bank_api__schemas________1`），既不可读也没必要；
`Literal` 把 `enum` 直接内联在那一列上。

### 2.2 `/v1/predict` 先收 `dict`，再手工校验

FastAPI 自动生成的 422 里，`loc` 是 `["body", "年龄"]`、`msg` 是英文
（`Input should be less than or equal to 95`）。要"指出是哪个字段"够用，但字段缺失、
类型错误、越界三种情况的 `msg` 风格不统一，前端要写三套判断。

所以端点签名收 `payload: dict[str, Any]`，内部 `input_model(**payload)`，捕 `ValidationError`
后抛 `RequestValidationError(_body_errors(...))`：`loc` 统一补上 `"body"` 前缀，`msg` 原样保留
pydantic 文案（中文提示留给前端按 `loc` 渲染）。实测越界返回
`422 [["body", "年龄"]] Input should be less than or equal to 95`。

### 2.3 `/health` 与 `/ready` 分开

- `/health`：进程活着就 200，**不读模型包**。K8s 的 liveness 用它。
- `/ready`：模型包加载成功且校验和通过才 200，否则 503，`detail` 写"模型包未就绪"。
  读模型包失败**不让进程退出**（`app.state["error"]` 记下原因），否则演示时一个坏包就让
  服务起不来，看不出是哪一步坏了。
- `/v1/model` 与 `/v1/predict` 在未就绪时返回 503 而不是 500：这是"暂时不可用"，不是代码 bug。

### 2.4 批量上限进配置

`configs/api.yaml` 的 `serving.batch_limit: 100`，同时体现在 OpenAPI 的 `maxItems` 和
运行时的 422 文案「一次最多 100 条，收到 N 条」。空列表也 422（前端空提交不是合法请求）。

### 2.5 预测记录只写决策事实

每行 `{ts, request_id, model_version, score, level, control}`，追加到
`data/processed/predictions.jsonl`（路径来自 `api.yaml`，进 `.gitignore`）。
**不写客户特征值**：记录是为了 M7 的对照组与回流，不是为了复现画像。
`control=true` 标记对照组请求（任务书 M7 的"是否对照"字段）。

### 2.6 服务不导入训练代码

`bank_api` 只依赖 `bank`（core）。预处理、派生、解释、包加载都在 core 里，
`training` 只在导出时被调用。这条由 `.importlinter` 的 independence 契约与
`tests/architecture/test_layers.py` 的 AST 检查守住，不是靠自觉。

## 3. 否掉的方案

| 方案 | 否掉的理由 |
| --- | --- |
| 手写 15 个字段的 pydantic 模型 | 与 `features.yaml` 两处维护，必然漂移；且改字段要动代码 |
| 用 `Enum` 表示类别 | `/docs` 里 component 名被改写成 `__`，不可读；多一层间接 |
| 直接让 FastAPI 用自动 422 | `msg` 英文、三种错误风格不一致，前端要猜 |
| 预测记录写 SQLite | 演示只需追加与 tail；多一个 schema 要维护，jsonl 一行一条更好 diff |
| 模型包缺失时让进程起不来 | 演示现场看不到 503/健康的区别，也看不出哪一层坏了 |
| `/predict` 出错一律 500 | 越界是**输入**问题（422），不是服务故障（500），混在一起前端无法提示 |

## 4. 后果

- 加字段：改 `features.yaml` → 重新 `bank_training.export` → 重启服务；`/docs` 自动跟着变。
- 前端只能通过 `/v1/model` 知道该画哪些控件；它不需要内置任何字段名。
- 422 的 `loc` 是稳定契约（`["body", 字段名]`），前端按它定位输入框。
- `python -m bank_api` 需要 `__main__.py`（第一次跑报
  `No module named bank_api.__main__` 才补上），现在一条命令起服务。
- 批量上限改配置即可，代码里没有第二个数字。

## 补充（2026-11-24）：422 只回 loc / msg / type，数值字段关掉 inf/NaN

起因：一条带 `NaN` 的请求体（JSON 里 `NaN` 这个 token 是 Python 的 `json` 默认接受的）过了 pydantic 的范围校验，
进了 `ValidationError` 的 `input` 字段；FastAPI 用 `json.dumps(..., allow_nan=False)` 序列化响应，于是**打 422 的时候
自己抛 ValueError**——本来该是「字段级错误」，实际会变成 500。

两处收口：

1. `_body_errors()` 只保留 `loc` / `msg` / `type`，不回显 `input` 与 `ctx`。顺带的好处是 422 不再把用户填的值原样回显
   （预测记录里本来也只留 `features_hash`，口径一致）。
2. 数值输入字段加 `allow_inf_nan=False`，`NaN` / `inf` 在 pydantic 层就被拒，`loc` 指到具体字段。

`tests/service/test_api.py::test_nan_is_422_not_a_crash` 守着这条（服务测试 22 → 23 项，总测试 366 → 367）。
