# ADR 0002：时间切分与建模窗口

- 状态：已采纳
- 日期：2026-11-22
- 相关：`docs/problem.md`、`docs/spec.md`、`docs/data_card.md`、ADR 0001

## 背景

原始表没有年份，早期文档据此认为"只能随机切分"。实际行序就是时间序（证据见 `data_card.md` 第 4 节：30 个月块、两次跨年回绕、块内日号从不回退、561 个日期全局单调）。同时，正例率随时间从 3.69% 涨到 53.22%，营销策略本身在从"广撒网"转向"精准打"。

任务书硬要求：建模样本 1.5–3 万行、正例 ≥1,000、至少有时间列或分组列。全量 45,211 行超出上限，必须裁窗口。

## 决策

1. **按时间切分**，切点 `2009-10-01`（月份边界）。
2. **建模窗口 A**：`2008-11-01 ~ 2010-11-17`，共 21,093 行、正例 4,109（19.48%）。
3. **训练集** `2008-11-01 ~ 2009-09-30`：17,537 行、正例 2,327（13.27%）。
4. **验证集** `2009-10-01 ~ 2010-11-17`：3,556 行、正例 1,782（50.11%），名额 356 人。
5. **缓冲期 0 天**，但切点只落在月份边界。
6. **不打乱、不分层、不切封存测试集**。

## 理由

- **为什么从 2008-11 起**：2008-05~08 是"名单全量外呼 + 三列全未知 + 从未联系 100%"的阶段，特征几乎无信息（正例率 3.7%），留着只会稀释信号；2008-10 只有 80 行、2008-12 只有 13 行，不能当起点或切点。
- **为什么切在 2009-10-01**：落在稳的月份边界上，避开十几行的稀疏月；前后两段都有足够样本（17,537 / 3,556），验证集占比 16.9%。
- **为什么缓冲 0 天**：标签在通话结束即得，不存在"用了未来信息"的问题；缓冲期是为"标签要等一段时间才成熟"的场景准备的（如 90 天复购），本项目的标签不需要等。仍按月份边界切，是为了不让同一批营销活动跨切点。
- **为什么不分层**：分层会让验证集类比例脱离真实时期分布，"验证集像未来"这个前提就没了。
- **为什么先不切封存测试集**：任务书一票否决"用测试集调参选模型"。演示阶段验证集足够；若要切，取验证集最后 3 个月（2010-09~11），只用一次，并写进模型卡。

## 被否掉的方案

| 方案 | 否掉的理由 |
| --- | --- |
| 随机切分 80/20 | 同一时期样本同时进训练与验证，验证集不再"像未来"，指标虚高（E5 实验反证） |
| 窗口 B：2009-01~2010-11 | 17,482 行可满足上限，但训练集只剩 14,862 行、验证集 2,620 行，且丢掉 2008-11~12 的 3,611 行信息 |
| 全量 45,211 行 | 超过任务书 3 万行上限 |
| 分层抽样 | 破坏类比例随时间的真实变化，校准指标失去意义 |
| 缓冲 30 天 | 标签即时可得，缓冲 30 天等于白丢 2009-10 整月 3,556 行里的前 30 天，没有收益 |
| 随机抽 2 万行（不按时间） | 抽样后时间序被破坏，且正例数会随抽样比例波动，不如整段裁窗口可解释 |

## 后果

- 训练期基率 13.27%、验证期 50.11%，模型概率会系统性偏低、Brier 会难看。这**不是 bug**，是漂移；指标必须带基率一起读（见 `pitfalls.md` 第 5 条）。
- 验证集一半是正例，所以"阈值 0.5"近似全员入选，主口径必须是名额制（356 人），阈值只作对照。
- E2（A/B 特征集）与 E5（时间 vs 随机切分）两个实验的数字依赖本 ADR，M3 必须回填到 `spec.md` 第 6 节。
- 窗口边界、行数、正例数要写进 M2 的 `manifest.json`；M2 的切分代码不得硬编码日期，读 `configs/base.yaml`。

## 复核方式

```powershell
.venv\Scripts\python.exe -m bank.profile
```

输出里 `A_train_2008-11_to_2009-09` 必须是 `17,537 / 2,327 / 13.27%`，`A_valid_2009-10_to_2010-11` 必须是 `3,556 / 1,782 / 50.11%`。
