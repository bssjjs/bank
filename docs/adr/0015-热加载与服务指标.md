# ADR 0015：热加载与服务指标

- 状态：已采纳（2026-11-24）
- 对应讲义：第二轮卷二 E-L2「不重启换模型」「服务指标」「一个 spec 两张卡」

## 背景

`models/serving/current.json` 是「现在线上用哪个版本」的唯一指针（ADR 0006）。原来的服务在
`create_app()` 里读一次模型包，之后再不重读——要换模型必须重启进程。这有两个问题：

1. 重启期间请求会失败（或至少 503），而换模型本来是一件不需要停机的事；
2. 答辩时「发布」和「上线」看起来是同一个动作，说不清哪一步真正生效。

另外服务侧完全没有可观测数据：出了 422 也好、某个等级占满也好，只能翻 `predictions.jsonl`
数行，没有「服务自己现在什么状态」的出口。

## 决定

### 1. 每个请求开始前读一次 `current.json` 的文本，变了才重新加载

`BundleStore`（`packages/api/src/bank_api/store.py`）做到三件事：

- **便宜**：每次请求只读一个几十字节的文件，与上次装上的文本比一下；一样就直接放行。
  对比"每请求重新加载模型包"：模型包 10 MB 级，每请求反序列化撑不住。
- **整包替换**：新包先 `B.load_bundle`（校验 checksum、模型文件大小与 sha256），
  再 `build_input_model`（生成请求模型）；两样都成功才整体换上去。
- **失败保留旧版本**：坏包、半截包、指针写成非 JSON，都只记 `last_reload_error` 与
  `reload_failures`，**旧模型继续服务**；坏指针文本会被记成"已尝试"，不会每请求重试同一个坏包；
  指针修好后下一次请求自动恢复。启动时没有包也不崩，等服务端把包发出来会自愈。

### 2. 指标契约 `service_metrics.v1`，走 `GET /metrics`

不做 Prometheus 客户端：本项目是单进程演示服务，没有采集端。`/metrics` 直接给 JSON：
`uptime_s`、`requests`、`by_route`（`"/v1/predict 200": 12` 这种形式）、`by_status`、
`predictions`、`by_level`、`latency_ms_mean`、`latency_ms_max`，外加 `model`（版本与是否可用）
与 `reload`（`loads`、`reload_failures`、`last_reload_error`、`hot_reload`）。

- 计数在 HTTP 中间件里做：`/health`、404、422 都算请求；预测数与等级只统计**成功返回**的预测；
- 指标里不出现任何客户特征值（有测试用 `json.dumps` 断言不含「退休」「81204」）；
- 进程重启后计数清零，这是"进程内计数器"的已知边界，写在这里而不是假装它持久。

### 3. 一个 spec，两份文档

规格只有一处：`configs/api.yaml`（批量上限、请求号前缀、预测记录路径）+ 模型包里的
`decision`（名额与等级切点）。两份文档分别是 `docs/model_card.md`（模型本身：数据、指标、
校准、切片、限制）与本 ADR（服务本身：路由、错误码、热加载、指标）。
不新建第三份"服务说明书"，避免同一件事写三遍然后互相对不上。

## 否掉的方案

| 方案 | 为什么不 |
| --- | --- |
| 后台线程定时轮询 `current.json` | 要管线程生命周期与轮询间隔，还多一个"多久算一次"的口径；按请求读一次更简单 |
| 每个请求都重新 `load_bundle` | 10 MB 模型 + joblib 反序列化，延迟不可接受 |
| 换模型时重启进程 | 换模型不该停机；而且答辩时演示不出"不重启"这个卖点 |
| 热加载失败就退出进程 | 半截包会让整个服务不可用；保留旧版本 + 记错误才是正确的降级 |
| 引入 Prometheus 客户端与 `/metrics` 文本格式 | 没有采集端，多一层依赖换不到东西 |
| 指标写进预测记录文件再由外部统计 | 记录是**逐条业务事实**，服务指标是**进程状态**，混在一起两边都难用 |

## 后果

- 每个请求多一次小文件 `read_text`（微秒级）；指针文件被锁/权限异常时按失败处理，不抛给调用方。
- 服务仍是单 worker（`python -m bank_api`）；多 worker 下每个进程各自热加载、各自计数，
  指标不是全局的——这一点写进服务卡，不假装它是集群指标。
- 新增 10 项测试（热加载 4、指标 6），总测试数 282 → 292；`tests/contract/test_openapi.py`
  的路由集合从 5 条改成 6 条（多 `/metrics`），这是有意的契约变更。
- 演示"不重启换模型"只需三步：起服务 → `python -m bank_training.export --version 1.1.0 --promote`
  → 再请求一次 `/ready`，版本已经变了，进程没重启。
