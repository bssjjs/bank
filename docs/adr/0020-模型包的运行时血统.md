# ADR 0020：模型包的运行时血统与版本闸门

- 状态：采纳（2026-11-24）
- 相关：`docs/adr/0006-模型包与发布.md`、`packages/core/src/bank/bundle.py`

## 背景

`bundle.json` 原来只记「训练来源」（`training.run_id` / `git_sha` / 两份数据指纹 / 训练时间），
没有记「在哪套运行时上训出来的」。模型是 pickle 的 `Pipeline`，sklearn 在小版本里也会改估计器内部结构，
换个环境加载可能不报错、但算出来的分数变了——这比报错更糟。

讲义第一轮卷三 D-L1 的硬性要求是：模型包 meta 要带 lineage 与 runtime，**sklearn 主次版本不同要拒绝加载**。

## 决定

1. `bundle.json` 新增 `runtime` 块，四个字段都是 `x.y.z` 形式的版本号：`python`、`sklearn`、`pandas`、`numpy`。
   导出时由 `bundle.runtime_now()` 从当前进程取，不由人填。
2. `load_bundle()` 在反序列化模型**之前**过一道闸门 `check_runtime()`：
   - sklearn 的 **主次版本**必须一致（`1.9.1` 与 `1.9.3` 放过，`1.6` 与 `1.9` 拒绝）；
   - Python 的 **主版本**必须一致（`3.12` 与 `3.13` 放过，`2` 与 `3` 拒绝）。
   不一致就抛 `BundleError`，消息里带「包里是哪个版本、现在是哪个版本、为什么拒绝」。
3. `/v1/model` 的 `describe()` 把 `runtime` 一起返回：前端和答辩现场都能看到「这个包是谁训的、在哪套环境训的」。
4. 老包（没有 `runtime` 字段）直接拒绝加载，不做「缺了就当没事」的兼容——本项目的包都能重导，兼容就等于留个后门。

## 否掉的方案

- **只警告不拒绝**：警告在日志里没人看，等发现分数变了已经上线了。
- **锁到补丁版本**：`1.9.1` 与 `1.9.3` 的差别通常只是 bug 修复与性能，锁死会让补丁升级都得重训，成本大于收益。
- **在包里塞一份 `requirements.txt` 让部署方自己比**：那是把判断推给人，且没人会真的逐个比。
- **只在导入时查一次、请求时不管**：热加载会在运行中换包，闸门必须跟着包走。

## 后果

- 升级 sklearn 的主次版本 = 必须重新导出模型包（一条命令），旧包会被拒绝加载而不是静悄悄地跑。
- `tests/unit/test_bundle.py` 新增 5 项（运行时写读、sklearn 主次不一致拒绝、Python 主版本不一致拒绝、手改 meta 加未知键拒绝、版本号格式非法拒绝），总测试数 361 → 366。
- 契约还是 `model_bundle.v1`，但字段集变了：这一版之前的包全部作废，本机 `models/serving/` 已重导（1.0.0，run_id `4e184fb8ab4a41b4bec61ce1bccfb828`）。
- 教训：凡是「加载时才能发现」的错，都该在加载时说出来，而不是等到第一次预测。
