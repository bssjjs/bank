# ADR 0014：预测记录 v2 与标签回流

- 状态：已采纳（2026-11-24）
- 相关：`packages/core/src/bank/predictions.py`、`packages/api/src/bank_api/app.py`、`packages/training/src/bank_training/backfill.py`、ADR 0008（漂移与回流）

## 背景

M5 写的预测记录只有 `{ts, request_id, model_version, score, level, control}`。它能回答"今天打了几个电话"，但回答不了讲义 F-L2 的问题：**打过电话的人后来到底认购了没有，模型当时排得对不对**。

要做回流，记录必须能和"后来的结果"对上号，而银行的合规要求是**日志里不写客户特征值**（AGENTS 第三节）。这两条不冲突，但需要设计：留一个不可逆的键来对号。

## 决定

### 1. 记录升到 `prediction_record.v2`

新增三样，其余字段不动：

| 字段 | 为什么 |
| --- | --- |
| `contract = "prediction_record.v2"` | 回读时版本不认识就报错，不猜字段含义 |
| `features_hash` | 输入 15 个必填字段的规范化 JSON 的 sha256。能去重、能发现"同一个人被打了三次"，但不可逆，日志里没有特征值 |
| `quota_frac` / `quota_n` | 这条是在什么名额口径下打的等级；回看历史决策不用再翻当时的模型包 |

`features_hash` 用 `bank.repro.sha256_json`，键序不影响结果（`sort_keys`），值一律 `str()` ——和内容指纹同一条规范化路径，避免两套哈希口径。

### 2. 对照组改成确定性抽样

`control` 默认 `None`：按 `sha256(f"{seed}:{request_id}")` 的前 4 字节折算成 [0,1) 的小数，小于 10% 就是对照组。这样：

- 同一个请求号永远得到同一个答案，重放同一批请求不用存随机数；
- 演练、测试、答辩现场都能复现；
- 想指定（例如演示"这一条我就要当对照组"）仍可以 `?control=true|false` 显式覆盖。

批次接口按**批次**算：一个批次一个请求号，整批共用一个标记，不会出现"同一批里一半进了对照组"。

### 3. 回流命令 `python -m bank_training.backfill --labels labels.csv`

输入两列 `request_id,label`（`1/0` 或 `是/否`），做四件事：

1. **只认能对上号的**：`request_id` 不在预测记录里就报错退出 1，不静默丢弃——标签来自别处说明数据管道接错了；
2. **不重复记账**：标签文件里同一个号出现两次直接拒绝；预测记录里同一个号有多条（重试）只取最后一条；
3. 输出 `data/processed/labeled.jsonl`（逐条：`request_id/label/score/level/model_version/control/predicted_at`）；
4. 输出 `data/processed/feedback.json`（契约 `feedback.v1`）：预测条数、贴标签条数、覆盖率、`training_allowed`（对照组剔除后的可重训条数）、三组认购率。

### 4. 对照组不进重训

`training_allowed` 就是"能拿去重训"的条数，等于"有标签且 `control=False`"。对照组的作用是**无偏估计**"如果什么都不做，会认购多少"，把它混进训练集会污染排序学习。ADR 0008 的三条重训条件之一"回流算的名额内精确率比模型卡低 5pp"，也必须用非对照组的样本算。

演练实测（12 条预测、10 条标签）：覆盖率 83.3%、`training_allowed` 10、全部认购率 0.4000、处理组 0.4000、对照组 0（12 条里没抽到，10% 抽样下概率约 28%，正常）。

## 否掉的方案

- **把特征值一起写进日志**：违反"日志里不写客户特征值"，且 45 万行级别的 jsonl 会越滚越大。
- **用数据库存记录**：本课程的数据量（每天几十到几百条）用 jsonl 足够，`git archive` 一打包就干净。
- **随机数抽对照组（`random.random()`）**：重放不可复现，测试也没法断言；哈希抽样免费解决。
- **标签对不上就跳过**：回流少算一部分样本，覆盖率数字会骗人；拒绝并报错更安全。
- **把 `control` 写死在请求里**：客户端能自己声明"我不算对照组"，对照组就失去意义；服务端抽样才是对的（显式参数只给演练用）。

## 后果

- 记录变宽，但每行仍是纯 JSON、无特征值；`predictions.jsonl` 与 `labeled.jsonl` 都在 `data/processed/`（不进 Git）。
- 回流的输入是"人给的标签文件"：真实场景由银行系统导出，这里只规定了文件名与两列格式。
- 测试 260 → 282 项（`tests/unit/test_predictions.py` 12 项、`tests/unit/test_backfill.py` 10 项）。
- 记录字段清单进 `architecture.md` §4 的"预测记录"契约；`feedbacks.json` 的字段进 §4 的"回流"契约。
