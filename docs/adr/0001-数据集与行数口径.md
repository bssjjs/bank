# ADR 0001：数据集与行数口径

- 状态：已采纳
- 日期：2026-11-22
- 相关：`docs/data_card.md`、`docs/spec.md`、ADR 0002

## 背景

任务书第 8 题指定 UCI Bank Marketing，没有指定必须采用哪一个变体。UCI 官方下载包同时包含 `bank-additional-full.csv`（41,188 行、20 个输入列）与 `bank-full.csv`（45,211 行、16 个输入列 + 1 个标签列，按日期排序）。本机 `data/bank-marketing.db` 是 45,211 行 × 17 列的中文 SQLite，对应 `bank-full.csv`。

**2026-11-26 更正**：本 ADR 初版曾把两份文件的行数差异解释成"是否合并同一客户重复联系"的去重口径。核对 UCI 官方数据集说明后确认，这是两份不同版本文件，不是同一份数据去重前后；该解释作废，采用本机库的决策不变。

现有口径层（`packages/core/src/bank/schema.py`、`dataset.py`、14 项单测）和时间轴证据全部建立在本机库上。

## 决策

**使用本机库 `data/bank-marketing.db`（45,211 行 × 17 列），建模单位是"一次联系尝试"，不重新导入 UCI 41,188 版。**

## 理由

1. 本机库保留同一客户的多次联系，"第几次打给他""上次结果如何"才有信息量；原始数据没有客户 ID，不能另行按人去重。
2. 时间轴（`rowid` → 30 个月块 → 561 个日期）是在这个库上验证的，换用字段口径不同的 `bank-additional` 需要重新验证，收益只是换到另一份官方变体。
3. 任务书只要求"结构化表格、1.5–3 万行建模样本、正例 ≥1,000"，没有要求行数与 UCI 一致；口径写清楚即可。
4. 45,211 行里有 24,118 行不在建模窗口（2008-05~08 与窗口外），处理方式是**按时间窗口裁剪**，不是删行——裁剪规则写进 manifest。

## 被否掉的方案

| 方案 | 否掉的理由 |
| --- | --- |
| 重新导入 41,188 的 `bank-additional` 版 | 输入列与数据口径不同，要重做 M2 全部与时间轴验证；不是对本机库的"修复" |
| 按客户去重 | 没有客户 ID，无法可靠判定"同一客户"，强行去重会误删 |
| 只用 UCI 原版做外部验证 | 两版口径不同，混用会让指标无法解释；留作 future work 并在模型卡写明 |

## 后果

- 所有报告里的行数、正例数必须写 **45,211 / 5,289（11.70%）**，不得引用 41,188 / 5,289 中的任一数字而不加说明。
- 答辩若被问"为什么和 UCI 的 41,188 行不一样"，答案是 `data_card.md` 第 3 节：官方有两份全量文件，本项目使用 45,211 行的 `bank-full.csv` 中文 SQLite 版本；现场跑 `uv run python -m bank.profile` 的第一行。
- `data_card.md` 第 3 节与本节必须同步修改，否则视为文档不一致。

## 复核方式

```bash
uv run python -m bank.profile
```

第一行必须打印 `行数 45,211，列数 17，正例 5,289（11.70%）`。
