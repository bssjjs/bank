# ADR 0022：解释必须能加回分数

## 背景

`/v1/predict` 每次返回「主要因素」，前端与答辩都会拿它解释「为什么这个人被排在前面」。这类解释最容易出的错不是算错贡献，而是**解释和模型不是一回事**：换了预处理、动了列顺序、换了模型种类，解释还能算出数字，只是那些数字加起来不等于模型真正用的那个分。

讲义 C-L1b 的原话是「贡献之和 + 基准 = logit」。这条不变量就是解释可信的唯一凭据——加不回去，它就只是好看的故事。

## 决定

1. `bank.explain.contributions(model, row) -> (intercept, list[Contribution])` 返回**全部列**的贡献，**不四舍五入**；`explain_one` 只是它的前 `top_k` 条，显示时才 `round(…, 6)`。
2. 不变量写成测试（`tests/unit/test_explain.py`，7 项）：对验证集前 20 行逐行断言
   `intercept + Σ contribution == model.decision_function(row)`（`assertAlmostEqual(places=10)`），
   以及 `sigmoid(decision_function) == predict_proba[:, 1]`。
3. 列名与变换后列数对不上时抛 `RuntimeError`（「改过预处理就得同步改 column_names」），不静默截断。
4. 非线性的最后一步（没有 `coef_`）直接拒绝解释，报出实际类型。

## 否掉的方案

- **只测「top 5 方向合理」**：方向对但幅度错，加不回分数，测不出问题。
- **在 `explain_one` 里直接四舍五入再相加**：算得回 0.538 不代表算得回 0.538184，精度在解释这层就该保留。
- **用 SHAP 做基准**：逻辑回归的线性 SHAP 与 `coef × 标准化值` 数学等价，装 shap 要拉 numba/llvmlite，还可能压低 numpy 版本（ADR 0005 已记）。
- **给树模型也做解释**：主模型是逻辑回归，树模型只作对照且不上线；真上线再写 TreeExplainer，并另写一份「和模型对得上」的测试。

## 后果

- 改预处理（`bank.features.build_preprocessor`）而不改 `column_names` 会让测试立刻红，这是想要的。
- 解释的数值口径与 `bundle.json` 无关，**不动模型包契约**，也不触发基线封条重写。
- 显示层仍然四舍五入到 6 位，前端展示口径不变。
