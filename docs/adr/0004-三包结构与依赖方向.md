# ADR 0004：三包结构与依赖方向

- 状态：已采纳
- 日期：2026-11-22

## 背景

任务书 M8 要求「分包与依赖方向」：`core` / `training` / `api` 三包，**训练与服务互不依赖**，并用 import-linter 或架构测试守住。M2 之前代码全在 `src/bank`，训练、服务、口径规则迟早会混在一个包里：一旦 `api` 为了复用几个常量去 `import` 训练代码，改训练就可能弄坏线上服务。

## 决定

1. 用 **uv workspace** 一个仓库三个包：

   | 目录 | 发行名 | 导入名 | 依赖 |
   | --- | --- | --- | --- |
   | `packages/core` | `bank-core` | `bank` | pandas / pyarrow / pydantic / pyyaml |
   | `packages/training` | `bank-training` | `bank_training` | `bank-core` + joblib / mlflow / scikit-learn |
   | `packages/api` | `bank-api` | `bank_api` | `bank-core` + fastapi / uvicorn |

2. 依赖方向只有一种：`training → core`、`api → core`。`training` 与 `api` 之间**没有任何边**。
3. 用 `.importlinter` 两条契约守：`forbidden`（`bank` 不许 import `bank_training` / `bank_api`）+ `independence`（`bank_training` 与 `bank_api` 互不依赖）。再配 `tests/architecture/test_layers.py` 用 AST 兜一层：有人绕过 lint-imports 直接改配置也能被测试逮住。
4. 现有 `src/bank` 整体迁进 `packages/core/src/bank`，**不保留第二份**。根 `pyproject.toml` 退化成 workspace 根（`[tool.uv] package = false`），只放 dev 工具与三包引用。
5. 仓库根用 `_find_root()` 逐级向上找 `configs/base.yaml` 定位仓库根，不再用 `parents[2]` 这种「数目录层级」的写法——层级一变就静默指错地方。

## 否掉的方案

- **单个包 + 目录分层**（`bank/training`、`bank/api`）：省事，但拿不到「训练与服务互不依赖」这条硬约束，任务书要的正是这条边；靠自觉守不住。
- **三个独立仓库**：课程交付要求一个仓库、一条质量门命令，拆开反而增加答辩时的解释成本。
- **`services/api` 命名**（参考项目 diabetes-risk 的写法）：任务书目录树写的是 `packages/{core,training,api}`，以任务书为准，评审不用在两套目录间翻译。
- **继续用 `bank.pth` 把 `src` 塞进 `sys.path`**：一次性的路径技巧，换个机器就失效；editable 安装是标准做法，且 `uv sync` 后 `import bank_training` 直接可用。

## 后果

- 加依赖必须用 `uv add`，且带 `UV_CACHE_DIR`/`UV_LINK_MODE`（沙箱挡了默认缓存目录），否则会报拒绝访问或让 uv 把自己删掉。
- 质量门多了一道：`lint-imports`（`scripts/ci.py` 第 4 道）。谁想「临时 import 一下」都会在本地就被拦住。
- 迁移后所有命令路径不变（`python -m bank.build` 等），因为导入名仍是 `bank`；变的只是文件位置与安装方式。
- `packages/training`、`packages/api` 目前只有 `__init__.py`，M3/M5 起往里面写业务代码，不再新建包。
