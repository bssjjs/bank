# ADR 0011：评估报全——13 个指标、两种名额口径、95% 区间、报告进训练运行

- 状态：已采纳（2026-11-24）
- 相关：ADR 0005（模型选择）、`docs/model_card.md`、`packages/training/src/bank_training/metrics.py`、`packages/training/src/bank_training/report.py`

## 背景

第一版只报 4 个数：AP、ROC-AUC、名额内精确率、名额内召回率，外加 Brier。问题有三个：

1. **报不全**。答辩问「名额内到底打中几个人、多打了几个、漏了几个」，第一版只有百分比，没有人数；
   Brier 报了但没用上；校准（ECE）根本没算。讲师讲义（第二轮卷一 C-L2a）要求指标能互相自洽、
   能手算出同一个数。
2. **只有一种名额口径**。上线按「前 356 名」取人，但页面上写着 `score >= 0.5`，两个口径选的人数不同
   （356 vs 574），不说清楚就是自相矛盾。
3. **没有区间**。3,556 人的验证集，精确率 0.7416 的抖动有多大没人知道；只报一个点估计，
   改一个特征掉 1pp 就分不清是信号还是噪声。
4. **报告不在产物里**。数字只在控制台滚动输出，mlflow 里只有一堆 metrics 标量，评审看不到一张能读的表。

## 决定

1. **13 个正式指标**，全部从同一个混淆矩阵与同一份分数推出：
   名额口径 8 个（精确率、召回率、F1、提升、准确率、打中人数、多打人数、漏掉人数）、
   排序口径 2 个（ROC-AUC、AP）、校准口径 3 个（Brier、对数损失、ECE）。
   自洽关系写进 `evaluate()` 的 docstring，并由 10 行手算例子的测试逐项核对。
2. **两种名额口径并列**：`two_views()` 同时给「前 k 名」（上线口径，356 人）与
   「固定阈值 0.5」（574 人），报告里两行分开写，谁都不许只贴一个。
3. **95% 区间**：`bootstrap_ci()` 按行重抽 200 次，每次把该行的 (分数, 标签) 一起抽走，
   名额按 `ceil(n_boot × frac)` 缩放——「第 k 名」始终是同一套排序逻辑，不另造口径。
   取 2.5% / 97.5% 分位，种子固定为 `metrics.SEED=42`，同一份数据两次运行区间完全一样。
4. **报告进训练运行**：主模型训练时生成 `data/processed/evaluation_report.md`
   （13 指标 + 区间 + 两种口径 + 对照表 + 「怎么读这张表」），同时作为产物记进该 mlflow run
   的 `evaluation/` 目录。

## 实现要点（踩过的坑）

- **ECE 的分箱边界要取整**。`np.linspace(0, 1, 11)` 的 0.3 是 0.30000000000000004，
  `np.digitize` 会把 0.3 分到「0.2–0.3」那一箱，手算与代码对不上（0.205 vs 0.285）。
  改成 `np.round(np.linspace(...), 12)` 后与手算一致。
- **Brier / 对数损失要先 clip** 到 `[1e-6, 1-1e-6]`，否则 sklearn 在极端分数上报 inf。
- **区间重抽要重算名额**。按比例缩放名额、而不是固定 356，否则小样本重抽时会取到超出样本的行。
- 报告只渲染 `Report` 里已有的数字，**不重新计算任何指标**——报告与 runs.json 永远一致。

## 否掉的方案

- **只报 AP 与精确率**：答辩必被问召回与人数，而且「精确率高、召回 0.15」本身就是要解释的取舍。
- **正态近似区间**：名额指标是离散比例、分布在 0.74 附近偏斜，正态近似会给负下界。
- **把区间当门槛**（比如「下界低于 0.70 就不许发布」）：样本只有 3,556 人，下界 0.7051 全靠数据量，
  拿它当门禁等于用验证集的抖动决定发布，违反 ADR 0005 的「验证集只报数」。
- **写一个 notebook 出报告**：不可复现、不进产物、无法与 run 绑定。

## 后果

- `python -m bank_training.train` 多花约 2–4 秒（200 次重抽 × 13 指标）；区间只对主模型算，
  对照模型只报点估计。
- 报告与 `runs.json`、模型卡三处数字必须一致：`tests/architecture/test_baselines.py` 会核对模型卡的
  4 位小数是否来自 `runs/m3-lr-主模型.json`。
- 报告里的区间是**验证集的抖动**，不是上线效果；跨期漂移（正例率 13% → 50%）比区间大一个量级，
  答辩时必须先讲漂移、再讲区间。
