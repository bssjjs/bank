# 0021 追踪协议与两个后端

## 背景

M3 起，训练、导出、漂移、演练、调参、对比这六条命令都在往 MLflow 里记东西。当时每个文件自己
`import mlflow`、自己 `set_tracking_uri`、自己 `start_run`，带来三个问题：

1. 单元测试想验证「这次运行记了哪些参数和指标」，就必须起一个真的 MLflow，跑得慢还依赖磁盘；
2. MLflow 的接口一年改两次，升级时要翻六个文件；
3. 讲义 C-L1c 的硬性要求是「MLflow 只在一个文件里导入，由契约守着」——我们显然不是。

## 决定

### 一、一个协议，两个实现

`packages/training/src/bank_training/tracking/base.py` 定义 `Tracker` 协议（`Protocol`，只看形状），
六个方法覆盖一次运行要记的全部东西：

| 方法 | 记什么 |
| --- | --- |
| `start_run(name)` | 上下文管理器，`with ... as run_id` 得到运行编号 |
| `log_params` | 输入配置（C、种子、名额……），**一律转字符串** |
| `set_tags` | 说明性字符串（数据指纹、切分点、git sha） |
| `log_metrics` / `log_metric` | 算出来的数（AP、名额内精确率……） |
| `log_artifact` | 随这次运行保存的文件；给了 `run_id` 就挂到那次运行 |

两个实现：

- `memory.py`：`InMemoryTracker`，记录留在内存里，给测试用；它在进程内没有外部依赖，跑一次
  「装配 → 训练 → 记录 → 断言」不到一秒。
- `mlflow_backend.py`：`MlflowTracker`，**本仓库唯一 import mlflow 的文件**。

### 二、后端也是注册表

沿用清洗规则（`rules.py`）与算法（`algorithms/`）的写法：`@tracker("名字")` 登记，重名直接报错。
`configs/tracking.yaml` 选后端：

```yaml
schema_version: 1
tracking:
  backend: mlflow
  experiment: bank-marketing
  tracking_uri: sqlite:///mlflow.db   # 相对路径按仓库根解析
```

### 三、这条规矩由架构测试守着，不靠人记得

`tests/architecture/test_layers.py::TrackingTest` 用 AST 扫 `packages/` 下所有 `.py`：
除了 `tracking/mlflow_backend.py`，任何文件出现 `import mlflow` / `from mlflow...` 都算失败。
另外两条断言：注册表里必须正好有 `memory` 与 `mlflow` 两个后端；`configs/tracking.yaml` 选的后端
必须在注册表里。

讲义原文建议用 import-linter 的契约写这条规矩。import-linter 的契约管的是「本仓库的模块之间」，
管不到「某个模块不许 import 第三方库」，所以这一条落在 AST 测试里，效果一样：红了 CI 就过不去。

### 四、配置单独一份，不动冻结指纹

`configs/tracking.yaml` 是独立文件，不并进 `configs/base.yaml`。理由与 `model.yaml`、`api.yaml`
一致：换后端、换实验名是工程设置，不该让 `bank.freeze` 的配置指纹失效（指纹一变，
`FROZEN.json`、基线封条、模型包里的 `config_fingerprint` 全要跟着重做，而数据一行没变）。

## 否掉的方案

| 方案 | 为什么不要 |
| --- | --- |
| 继续每个文件直接 import mlflow | 测试要起 MLflow；升级要改六处；讲义明确要求「只在一个文件」 |
| 把 mlflow 包一层薄函数（模块级函数 + 全局变量） | 全局状态，测试之间会串；也没法在配置里换后端 |
| 用 `entry_points` 做插件发现 | 本项目只有两个后端，注册表 + 惰性导入够了；entry_points 要打包才能测 |
| 后端直接写进 `base.yaml` | 会让冻结指纹跟着工程设置变，见上 |
| 让 `Tracker` 继承 `ABC` 强制实现 | `Protocol` 更轻：内存后端不必继承也能当 Tracker 用，测试替身写起来短 |

## 后果

- 加一个后端 = 一个文件 + `@tracker("名字")` 登记；编排层一行不用改。
- 测试里想「把整条训练跑一遍、只看记了什么」：`get_tracker("memory")`，不需要磁盘。
- `train.py` 的收尾打印从「mlflow：…」变成「追踪：mlflow，5 个 run」——后端名字由后端自己报，
  换后端时日志不会撒谎。
- 命令行上的 `--no-mlflow` 保留原样：它表达的是「这次别记」，跟换后端是两件事。
- 测试 367 → 389（追踪层 19 项 + 架构 3 项）。

## 复现

```powershell
uv run python -m pytest tests/unit/test_tracking.py tests/architecture/test_layers.py -q
uv run python -m bank_training.drift     # 走 mlflow 后端，打印新的 run_id
uv run python scripts\ci.py              # 末行「质量门：全绿」
```
