# F6：告警与定时检查

## 是什么

`python -m bank_training.watch` 一次跑完三件事：读 `data/processed/drift.json` 按阈值分级、读 `data/processed/feedback.json` 看标签覆盖率、可选读服务 `/metrics`；把告警投递到 `configs/watch.yaml` 配的渠道，并把这一轮写成 `data/processed/watch.json`（契约 `watch_report.v1`）。有 `alert` 级告警时退出码 1。

## 谁用

- **发布与服务**（M5/M7 负责人）：每天早上看一眼，或者挂进任务计划程序。
- **答辩时的评审**：用 `drill`（F7）造一次漂移，再跑 `watch`，看"监控真的会叫"。
- **重训决策的人**：看到 `retrain/psi_two_runs` 才需要动，单次越线只是提醒。

## 输入

- `data/processed/drift.json`（`bank_training.drift` 的产物）：每个特征的 `psi` 与 `label.relative_change_pct`。
- `data/processed/feedback.json`（可选，`bank_training.backfill` 的产物）：`coverage`。
- `--base-url`（可选）：`GET /metrics` 的 JSON；不给就不查服务。
- `configs/watch.yaml`：阈值与渠道。
- `data/processed/watch_history.jsonl`：上一轮的 `breaches`（只有这一轮用它判断"连续两次"）。

## 输出

- 终端逐条 `[level] source/code: message`，末行「检查完成：info/warn/alert 计数」。
- `data/processed/watch.json`：`contract/ts/drift_report/counts/breaches/alerts[]`。
- `data/processed/watch_history.jsonl`：每轮一行 `{ts, breaches}`。
- 渠道副作用：`console` 打印、`file` 追加 JSONL、`webhook` POST（超时 3 秒）。
- 退出码：0 无 alert；1 有 alert；2 命令行参数看不懂。

## 契约

- 报告顶层：`contract="watch_report.v1"`、`ts`（UTC，带 Z）、`drift_report`、`counts`（三档计数）、`breaches`（本轮越告警线的特征名，排序）、`alerts`（`level/source/code/message`，有数值时带 `value`）。
- 代码：`psi_<特征>`（`drift`）、`psi_score`、`label_shift`（`drift` 或 `feedback`）、`coverage_low`（`feedback`）、`missing_feedback`（`feedback`）、`service_unreachable` / `model_unavailable` / `reload_failures`（`service`）、`psi_two_runs`（`retrain`）、`webhook_failed`（`channel`）。

## 错误边界

- `drift.json` 不存在 → `WatchError`「找不到漂移报告…先跑产出它的命令」。
- `feedback.json` 不存在 → 不报错，给一条 `missing_feedback` 的 warn（回流这条线是瞎的，得让人知道）。
- 配置写错（未知键、渠道 kind 不认识、file 没 path、告警线低于关注线）→ `WatchError` 并指出 `thresholds.psi_alert: ...` 这样的位置。
- `features` 既不是列表也不是对象，或某行缺 `feature/psi` → `WatchError`。
- webhook 连不上/超时 → 返回 `channel/webhook_failed`（warn），本轮其他告警照常落盘。
- 服务没起 → `service/service_unreachable`（warn），退出码不受影响（除非同时有 alert）。

## 不做

- 不做常驻守护进程、不做 Prometheus 导出、不自动重训、不在告警里写客户特征值。
- 不在告警里重新算 PSI：`watch` 只读 `drift.json`，重算 PSI 是 `bank_training.drift` 的事（一处一个职责）。

## 怎么验收

```powershell
.venv\Scripts\python.exe -m bank_training.drift          # 先有 drift.json
.venv\Scripts\python.exe -m bank_training.watch           # 第一轮：7 条 alert、5 条 warn
.venv\Scripts\python.exe -m bank_training.watch           # 第二轮：多 psi_two_runs，退出码 1
.venv\Scripts\python.exe -m pytest tests/unit/test_watch.py -q
```

## 为什么这样定

- **一次发一批**：一轮里 6 个特征越线是常态，逐条推送会把人训练成忽略告警。
- **渠道失败降级成告警**：告警发不出去这件事本身要被知道；渠道抛异常把整轮检查搞挂，等于最需要监控的时候监控先死。
- **连续两次才建议重训**：PSI 是抽样量，单次越线可能只是这一批人不同；ADR 0008 的三条重训条件里，这条最容易自动化。
- **退出码 1**：让 `watch --no-send` 能进流水线当判定，而不只是给人看的一份报告。
