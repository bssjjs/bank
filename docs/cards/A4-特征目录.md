# A4 · 特征目录（`bank/catalog.py` + `configs/features.yaml`）

## 1. 这个模块是什么

每个字段的**类型、范围、取值、中文名、是否禁用、禁用理由**的唯一出处。33 个字段一条一条写死，
代码里不许再出现第二份（不许在训练里写 `if col == "年龄"`，也不许在前端硬编码字段清单）。

目录与 `schema.py` 是"规格 + 实现"的关系：目录说"职业是 12 个取值之一"，`schema.py` 负责把
Excel 里的中文列转成模型要的数字。两边说的必须是同一件事，对不上就在加载时抛错。

## 2. 谁用它

`clean.py`（范围白名单）、`dataset.model_features()`（可进模型的列）、`bundle.py`（bundle 的
`inputs` 与 `feature_types`）、`bank_api/schemas.py`（422 的字段名/范围/枚举）、前端（表单控件）、
`drift.py`（哪些列要盯）。

## 3. 输入

`configs/features.yaml`：`schema_version: 1` + `fields:` 列表。每个字段：

```yaml
- name: 年龄            # 必填，与 DataFrame 列名逐字一致
  type: numeric         # numeric | binary | categorical | ordinal | time | date | id
  display: 年龄          # 必填，中文名，接口文案与页面标签都用它
  role: feature         # feature（进模型）| source（只用于派生）
  derived: false        # 是否派生列（由本仓库代码算出来）
  forbidden: false      # 禁用列：永不进特征
  reason: ...           # forbidden: true 时必填
  unit: 岁              # 可选，仅用于文案
  min: 18               # numeric/time 必填
  max: 95
  categories: [是, 否]   # binary/categorical/ordinal 必填
```

## 4. 输出

`CatalogSpec`（pydantic，frozen）：`by_name()`、`field(name)`、`feature_names()`（24 列）、
`forbidden_names()`（8 列）、`fingerprint()`（sha256，64 位十六进制）。

## 5. 契约（公开接口）

```python
CATALOG_PATH: Path
REQUIRED_FORBIDDEN = (通话时长, 距上次联系天数, 是否认购)
class CatalogError(RuntimeError)
class FieldSpec(BaseModel)     # extra="forbid", frozen=True
class CatalogSpec(BaseModel)   # extra="forbid", frozen=True
load_catalog(path: Path = CATALOG_PATH) -> CatalogSpec
assert_agrees_with_schema(spec: CatalogSpec) -> None
```

## 6. 错误与边界

| 情况 | 行为 |
| --- | --- |
| 禁用列没写 `reason` | `CatalogError`：`禁用列 X 必须写 reason：答辩要能一句话解释为什么禁用` |
| numeric/time 没写 min/max | 报错 |
| min > max | `CatalogError`：`X 的 min 不能大于 max` |
| binary 的 categories 不是 2 个 | `CatalogError`：`X 是 binary，categories 必须正好两个` |
| 字段名重复 | `CatalogError`：`字段名重复：['职业']` |
| 三条关键禁用列缺一条 | `CatalogError`：`禁用列必须出现在目录里：['是否认购']` |
| 关键禁用列没标 `forbidden: true` | `CatalogError`：`X 必须标 forbidden: true` |
| 目录与 `schema.py` 的列集合不一致 | `CatalogError`：`特征集 A 用到但目录没标可用的列：[...]` |
| `role: source` 的列被模型用到 | 同上，报"没标可用" |

## 7. 不做什么

- 不做自动发现字段：目录是**手写**的清单，新增一列必须改这里，改不动就说明设计该改；
- 不描述统计分布（均值/分位数）：那是数据卡与 PSI 的事；
- 不做版本迁移：目录改了就是新版，指纹会变，旧模型包按老目录走（bundle 自带 `catalog_fingerprint`）；
- 不写默认值填充策略：填补发生在 Pipeline 里，目录只说"允许什么值"。

## 8. 怎么验收

```powershell

.venv\Scripts\python.exe -m pytest tests/unit/test_catalog.py -q        # 单测
```

考卷覆盖：33/24/8 的数量、24 列与 `model_features("A")` 一致、禁用列必有理由、
数值范围越界、bin 三值、未知 type、重名、删除关键禁用列、把特征降级成 source、
改范围导致指纹变化。

## 9. 为什么这样定

- **为什么用中文列名当 `name`**：业务方是银行，表头就是中文；再起一套英文名就要维护映射，
  而映射本身是最容易走形的口径（v0 项目就是这么把「已确诊」悄悄选进特征的）。代价写在 ADR：
  接口与页面的键也是中文，跨语言调用要额外编码。
- **为什么把三条禁用列写进代码常量**（`REQUIRED_FORBIDDEN`）：目录是 YAML，改起来太容易；
  把"通话时长 / 距上次联系天数 / 是否认购绝不能被解禁"钉在代码里，删掉就会加载失败。
- **为什么加载时就要与 `schema.py` 对账**：两份名单一旦漂移，最坏的结果是"训练用了 24 列，
  服务按 25 列校验"，线上才发现；对账放在启动时，错误发生在能改的时候。
