# A2 · 指纹与规范化（`bank/repro.py`）

## 1. 这个模块是什么

把"同一份东西"变成一个 64 位十六进制字符串的四件小工具：

- `sha256_file(path)`：文件字节指纹（1 MiB 分块读）；
- `canonical_json(obj)`：键排序、无空格、不转义中文的规范化 JSON；
- `sha256_json(obj)` / `sha256_records(records)`：对象（记录列表）的指纹；
- `sha256_table(df)`：表内容指纹 = 规范化 CSV 的 sha256。

外加两个"报告事实用"的探针：`git_sha()`、`git_dirty()`。

## 2. 谁用它

`freeze.py`（写到 `manifest.json` / `FROZEN.json`）、`config.py`（配置指纹）、
`catalog.py`（目录指纹）、`bundle.py`（模型包 checksum）、`scripts/freeze_baseline.py`
（基线封条）、`train.py`（run 的 tags）。它处在**最底层**：除了 pandas 之外不依赖本仓库任何模块。

## 3. 输入

| 函数 | 输入 | 约束 |
| --- | --- | --- |
| `sha256_file` | `Path` | 必须是已存在的普通文件；不存在直接 `FileNotFoundError` |
| `canonical_json` | 任意可 JSON 化对象，另支持 `Path` / `date` / `datetime` | 其它类型抛 `TypeError`，不许悄悄 `str(obj)` |
| `sha256_table` | `DataFrame` | 列序、行序由调用方负责固定；空值在本数据集不存在（「未知」是一个取值） |

## 4. 输出

- 所有指纹函数返回**小写 64 位十六进制**字符串；
- `git_sha()` 返回 40 位提交号；不在仓库里/没装 git 时返回 `None`（不抛异常）；
- `git_dirty()` 返回 `bool`；取不到状态时返回 `None`。

## 5. 契约（公开接口）

```python
sha256_file(path: Path) -> str
sha256_text(text: str) -> str
canonical_json(obj: Any) -> str
sha256_json(obj: Any) -> str
sha256_table(df: pd.DataFrame) -> str
sha256_records(records: list[dict[str, Any]]) -> str
git_sha() -> str | None
git_dirty() -> bool | None
```

## 6. 错误与边界

- 未知类型 → `TypeError: canonical_json 不认识 set`（而不是把对象 repr 进指纹——那会让指纹随内存地址漂移）；
- `Path` 统一转 `as_posix()`：Windows 的 `data\frozen` 与 Linux 的 `data/frozen` 必须是同一个指纹；
- `datetime` 走 `isoformat()`，带微秒就带微秒——不做"截断到秒"的猜测；
- 表指纹对**列序**和**行序**都敏感：数据集里行序就是时间序，排序会改变"第几行是第几天"；
- 浮点统一 `%.10g`：`0.1` 与 `0.1000000000001` 视为同一个数。这是有意取舍（见 §9）。

## 7. 不做什么

- 不做加密/签名：这里要的是"内容变了能被发现"，不是"防篡改"；
- 不做跨表合并指纹：一个表一个指纹，合并会导致"改哪里都变"的假警报；
- 不读数据库、不碰业务口径：它不知道「通话时长」是什么，只知道字节和文本；
- 不缓存、不写文件。

## 9. 为什么这样定

- **为什么不用 `pickle` / `repr` 算指纹**：序列化结果会随 Python 版本、对象地址变化，指纹就失去"跨机器可比"的意义。
- **为什么 `%.10g` 不是全精度**：pandas 在不同版本上 `repr` 浮点的末位可能不同；10 位有效数字之后的变化在业务上无意义，却会让"内容没变"被误判成"数据变了"。代价写在 ADR 0003：极端情况下第 11 位之后的变化查不出来。
- **为什么 `git_sha` 失败返回 `None` 而不抛**：它只用于"这批结果是在哪个提交上跑出来的"这类元信息；拿不到时结果本身仍然有效，不该因此让训练崩掉。
