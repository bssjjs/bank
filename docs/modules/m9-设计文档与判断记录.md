# M9 设计文档与判断记录

## 目标

让没参与开发的人（和答辩老师）只读文档就能判断：我们懂不懂这个系统、每个决定为什么这么定、哪些没做。

## 验收

- `docs/architecture.md` 七项齐全：需求、需求→机制对照表、模块图与分层图、五份契约字段、目录树、一次预测与一次发布流程、做了什么没做什么。
- ADR 8 份（要求 ≥6），每份含背景、选项、决定、后果：0001 数据集与行数、0002 时间切分、0003 指纹与冻结、0004 三包结构、0005 模型选择、0006 模型包与发布、0007 服务契约与错误码、0008 漂移与回流。
- 模块卡 9 张（本文所在目录），每张含目标 / 验收 / 不做。
- `README.md` 能让人从零跑起来；`AGENTS.md` 写清规矩、命令、当前进度与已知缺口。
- 贡献表：`docs/contributions.md`。
- 四个里程碑 tag：`m1-topic` / `m2-design` / `m3-mvp` / `final`。

## 不做

- 不照抄任务书或参考资料（数字、结论、失败尝试都来自本仓库的真实运行）。
- 不写「将来会做」当已完成：没做的进「没做什么」表。
- 不在文档里放没跑出来的数字：每个指标都要有命令出处。
