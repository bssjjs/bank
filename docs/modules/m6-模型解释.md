# M6 模型解释

## 目标

让人能回答两个问题：模型整体靠什么特征排序；单条客户为什么得到这个分数、这个等级。解释必须和模型同源，不能另训一个“解释模型”或另写一套预处理。

## 验收

- 全局解释：`packages/training/src/bank_training/global_explain.py` 用线性贡献（系数 × 标准化值，等价线性 SHAP）与置换重要度（AP 下降，固定种子）两张表对照；蜂群图落 `data/processed/global_explain_beeswarm.png`，Markdown 落 `data/processed/global_explain.md`。
- 结论进评估报告：`train.py` 把同一份全局解释追加到 `reports/evaluation_report.md`，并把 md/png 作为产物记进主模型 run；不是只留一个孤立文件。
- 单条解释：`packages/core/src/bank/explain.py` 的 `contributions()` 返回截距与全部列贡献，满足 `截距 + Σ贡献 == decision_function`（`tests/unit/test_explain.py` 用 `places=10` 守住）；`explain_one_with_base()` 额外返回 `base_value`、`base_probability` 与单位 `log_odds`。
- 服务透出：`packages/core/src/bank/bundle.py` 的 `explain_with_base()` 与 API 的 `Prediction` 一并返回 `base_value`、`base_probability`、`contribution_unit` 和 top 5 因素；`tests/unit/test_explain.py`、`tests/service/test_api.py` 守住字段与可加性。
- 局限写清：背景数据只来自训练集；相关特征之间会分摊贡献；解释是模型内部归因，不是因果；分数经过校准层时，解释解释的是 log-odds 排序分，不是最终概率。

## 不做

- 不引入 SHAP 的 Kernel/Tree 解释器做第二套口径；主模型是线性模型，线性贡献就是精确的 SHAP 值。
- 不在前端或 API 里另算贡献，统一走 `explain.py`。
- 不做因果/增量结论（“打了比不打好多少”），数据没有真正对照组。
- 不把贡献值四舍五入后再加回；存原始 float。
