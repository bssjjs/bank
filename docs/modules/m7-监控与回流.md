# M7 监控与回流

## 目标

回答「线上数据还像训练时吗」「模型还准吗」「什么时候该重训」，并把标签回流、对照组与重训条件设计清楚。

## 验收

- `.venv\Scripts\python.exe -m bank_training.drift` 对「线上」批次跑 PSI：联系月份 3.4028、住房贷款 0.8087、上次营销结果 0.6573、职业 0.4583、历史联系次数 0.3500、年龄 0.2797 为严重；score PSI 1.0851；正例率 13.27% → 50.11%（+277.66%）。
- 分箱边界只取训练集分位数、缺失单独一箱、类别未见值合并「其他」、只看 15 个原始输入 + score。
- 输出契约 `drift_report.v1` 到 `data/processed/drift.json`，并记 `m7-drift` run。
- 设计（文档）：`docs/adr/0008-漂移监控与回流.md` —— predictions.jsonl ↔ labels.jsonl 按 request_id join；`control=true` 按 10% 随机抽作对照组且不进重训；三条重训条件（任一输入 PSI≥0.25 连续两月 / 回流名额内精确率比模型卡低 5pp / 正例率变化 ±50%）。
- 测试：`tests/unit/test_drift.py` 11 项。

## 不做

- 不做自动重训与调度（三条触发条件落文档，重训命令仍是 `freeze → train → export`）。
- 不做监控面板与告警通道（`drift.json` 是数据源）。
- 不做自适应分箱（边界必须冻结在训练集，否则 PSI 自己会漂）。
- 不做按分数抽对照组（必须随机，否则对照组本身有偏）。
