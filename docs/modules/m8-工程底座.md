# M8 工程底座

## 目标

让五个人同时改代码也不会互相踩：分包与依赖方向、配置强校验、字段唯一出处、规则注册表、一条命令的质量门。

## 验收

- 三包 `packages/{core,training,api}`，导入名 `bank` / `bank_training` / `bank_api`；`.importlinter` 两条契约（core 是底座、training 与 api 互不依赖），并有 `tests/architecture/test_layers.py` 9 项 AST 兜底。
- 四份 YAML 都严格读：未知键、重复键、越界值、跨段矛盾立即报错（`base.yaml` / `model.yaml` / `api.yaml` / `features.yaml`）。
- 特征目录 `configs/features.yaml`：33 个字段，8 个禁用列必须带理由，与 `schema.py` 的列清单对账（`tests/unit/test_catalog.py` 13 项）。
- 清洗规则注册表 `rules.py`：加规则只写一个函数，重复编码报错，台账顺序可 diff（`tests/unit/test_rules.py` 5 项）。
- 质量门 `.venv\Scripts\python.exe scripts\ci.py` 末行「质量门：全绿」，五道门：ruff check、ruff format --check、mypy、lint-imports、pytest。
- 测试 145 项；`AGENTS.md` 写清规矩、命令与进度。

## 不做

- 不做容器化与云 CI（课程项目，本地一条命令足够）。
- 不做多环境配置（dev/prod）：只有一份口径，多环境会分裂数字。
- 不引入额外框架（DVC、Prefect 等）：冻结与指纹自己实现，行为可读。
- 不为了过门禁写 `# type: ignore` / `# noqa`。
