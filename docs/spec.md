# 口径规格表（M1）

> 口径 = 换一批数据也不会变的规定。本文件里每一条都对应代码里的一个常量或函数，改口径必须改这里并说明理由。
> 逐列事实来自 `python -m bank.profile`（见 `data_card.md` 的复现命令），不是凭印象写的。

## 1. 原始 17 列逐列判定

「预测时点可得」是这一列能不能进模型的唯一判据：预测时点是**通话发起前一刻**。

| # | 列名 | 类型 | 取值 | 预测时点可得 | 用途 | 处理规则 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 年龄 | int | 18–95 | 是 | 特征 | 1%/99% 分位裁剪 + 标准化（阈值在 Pipeline 里 fit） |
| 2 | 职业 | 11 类 + 「未知」 | 蓝领工人…学生、未知 | 是 | 特征 | 「未知」保留为独立类别，one-hot |
| 3 | 婚姻状态 | 3 类 | 已婚 / 未婚 / 离婚 | 是 | 特征 | one-hot |
| 4 | 教育程度 | 3 档 + 「未知」 | 小学 / 中学 / 高等教育 / 未知 | 是 | 特征 | 序编码 1/2/3 + 单独「未知」哑变量，未知不占顺序位 |
| 5 | 是否信贷违约 | 2 类 | 是 / 否 | 是 | 特征 | 映射 1/0 |
| 6 | 账户余额 | int | −8,019 ~ 102,127 | 是 | 特征 | 分位裁剪 + 标准化 |
| 7 | 住房贷款 | 2 类 | 是 / 否 | 是 | 特征 | 映射 1/0 |
| 8 | 个人贷款 | 2 类 | 是 / 否 | 是 | 特征 | 映射 1/0 |
| 9 | 联系方式 | 3 类 | 手机 / 固话 / 未知 | 是 | 特征 | 「未知」是真实客群（13,020 条），保留为类别 |
| 10 | 联系日期 | int | 1–31（月内第几天） | 是 | 特征 | 周期编码 sin/cos（周期 31） |
| 11 | 联系月份 | 中文月份 | 一月 … 十二月 | 是 | 特征（A 集） | 映射 1–12 + 周期编码 sin/cos（周期 12）；B 集整组剔除，见 ADR 0002 |
| 12 | 通话时长 | int | 0–4,918 秒 | **否** | **禁用** | 通话结束后才有值，属于结果泄漏，见第 3 节 |
| 13 | 本次联系次数 | int | 1–63 | 是 | 特征 | 分位裁剪 + 标准化 |
| 14 | 距上次联系天数 | int | −1（从未联系）或正天数 | **否（原列）** | 派生后禁用原列 | −1 是哨兵不是天数，拆成 3 列，见第 2 节 |
| 15 | 历史联系次数 | int | 0–275 | 是 | 特征 | 分位裁剪 + 标准化 |
| 16 | 上次营销结果 | 4 类 | 未知 / 失败 / 其他 / 成功 | 是 | 特征 | one-hot；未知占 36,959 条，是类别不是缺失 |
| 17 | 是否认购 | 2 类 | 是 / 否 | 标签 | **标签** | 只有它是标签，不得进特征 |

## 2. 派生列（确定性转换，可单测）

| 派生列 | 定义 | 为什么需要 |
| --- | --- | --- |
| `label` | `是否认购 == "是"` → 1，否则 0 | 统一目标列名，避免中文列名进模型代码 |
| `是否被联系过` | `距上次联系天数 != -1` → 1 | 哨兵必须显式表达，否则树模型把 −1 当"最近联系" |
| `距上次联系天数_log` | `log1p(天数)`，未联系记 0 | 天数右偏严重；0 与真实值不撞（≥1 天时 log1p ≥ 0.693） |
| `距上次联系天数档` | 0=未联系，1=(0,30]，2=(30,90]，3=(90,180]，4=(180,365]，5=365+ | 业务阈值分档，实测认购率不单调，保留高低起伏 |
| `信息完整度` | 3 − 三列「未知」的个数 | 「未知」个数与认购率单调下降 |
| `教育程度序` | 小学/中学/高等教育 = 1/2/3，未知留空 | 有序变量只授予真实学历 |
| `教育程度_未知` | `教育程度 == "未知"` → 1 | 未知是类别，单独一列 |
| `月份序` / `月份_sin` / `月份_cos` | 中文月份 → 1–12 及其周期编码 | 让十二月与一月在数值上相邻 |
| `日期_sin` / `日期_cos` | 月内第几天 → 周期编码（周期 31） | 发薪日/月初月末效应 |
| `序号` | `rowid`，原始表的行号 | **时间序的载体**，见 `data_card.md` 第 4 节；不是特征 |
| `年份` / `重建日期` | 由 `序号` + 月份 + 日号重建 | 时间切分的依据；不是特征（避免把年份当趋势学） |

## 3. 禁用列清单（硬约束）

| 禁用列 | 理由 | 怎么守 |
| --- | --- | --- |
| `通话时长` | 结果泄漏：只有通话结束才知道。单变量 AUC 就 0.8076，比很多完整模型都高 | `schema.EXCLUDE_COLS` + `dataset.model_features()` 里的断言；M8 起再加 `configs/features.yaml` 的 `forbidden` 段与 core 层校验；有单测 |
| `距上次联系天数`（原列） | −1 是「从未联系」哨兵，占 81.74%。直接入模：树模型把 −1 当最近联系、线性模型得到负天数 | 同上；派生三列替代 |
| `是否认购` | 标签本身 | 不在任何特征清单里；`model_features()` 只从 `NUMERIC/CATEGORICAL/ORDINAL/TIME_COLS` 组装 |

补充两条**不是禁用但必须写进模型卡**的提醒：

- `职业`、`教育程度`、`婚姻状态` 在现实世界里是受保护/敏感属性，本模型只用于"打电话排序"，不得用于信贷审批、定价等个体决策。
- `账户余额` 可能间接携带收入信息，报告里不展示单条客户的具体数值，只展示贡献方向。

## 4. 切分口径

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 建模窗口 | 2008-11-01 ~ 2010-11-17（21,093 行，正例 4,109，19.48%） | 从 2008-11 起是为了跳过 2008-05~08 的「名单全量外呼 + 全部未知」阶段；见 ADR 0001 |
| 训练集 | 2008-11-01 ~ 2009-09-30（17,537 行，正例 2,327，13.27%） | 按时间前半段 |
| 验证集 | 2009-10-01 ~ 2010-11-17（3,556 行，正例 1,782，50.11%） | 按时间后半段；**封存测试集本阶段不切**，见下 |
| 切点 | 2009-10-01（月份边界） | 不落在月中，避免同一批营销活动跨切点 |
| 缓冲期 | **0 天** | 标签在通话结束即产生，不存在"未来信息"；但仍按月份边界切，防止同一活动跨期。缓冲为 0 的理由写进 ADR 0002 |
| 打乱 | 不做 | 打乱即破坏时间序，等价于把未来样本放进训练 |
| 分层 | 不做 | 分层抽样会让验证集的类比例不再反映真实时期，违背"验证集要像未来"的初衷 |
| 封存测试集 | 演示阶段不切；若要切，取验证集最后 3 个月（2010-09~11）并只用一次 | 任务书一票否决"用测试集调参选模型"，所以宁可不切，答辩时说明 |

## 5. 标签与名额口径

- **标签**：只接受 `是` / `否` 两种取值；出现其它取值或空值直接报错（不静默当负例），并把命中行数写进清洗台账。
- **名额比例**：`quota_frac = 0.10`（配置项）。名额人数 `quota_n = ceil(验证集行数 × 0.10) = ceil(355.6) = 356`，训练时打印。
- **入选规则**：按分数降序取前 `quota_n` 人；分数相同按 `序号` 升序（确定性，保证可复现）。
- **阈值**：0.5 同时算并记录，仅作对照，不作为验收口径（基率 50% 时阈值 0.5 近似全员入选）。

## 6. 朴素版与规范版对照（一次只改一处）

每个实验只改一处、其余完全不变，在同一验证集（3,556 人、正例 1,782、基率 50.11%）、同一名额（356 人）下比较。数字由 `python -m bank_training.experiments` 写进 mlflow 并回填下表，一条命令可复现。

| 编号 | 只改这一处 | 对照 | 记录指标 | 预期方向 | 实测（验证集 356 名额） |
| --- | --- | --- | --- | --- | --- |
| E1 | 把 `通话时长` 加进特征 | B 集（21 列） | AP / ROC-AUC / 名额内精确率 | 上升 → 证明泄漏 | AP 0.6571 / AUC 0.6762 / 精确 0.7893（对照 0.6498 / 0.6438 / 0.7416） |
| E2 | 特征集 A（含月份三列）→ B（剔除） | 同一切分 | 同上 | A 更高（月份带时期信息） | A：0.5959 / 0.6116 / 0.6180；B：0.6498 / 0.6438 / 0.7416 → 与预期相反，A 反而差（ADR 0005） |
| E3 | 「未知」保留为类别 → 填训练集众数 | B 集 | 同上 | 下降 → 证明未知不是缺失 | AP 0.6204 / AUC 0.6223 / 精确 0.7191（对照 0.6498 / 0.6438 / 0.7416） |
| E4 | `距上次联系天数` 用派生三列 → 原列直接入模 | B 集 | 同上 | 下降 / 校准变差 | AP 0.5996 / AUC 0.6125 / 精确 0.6236（对照 0.6498 / 0.6438 / 0.7416） |
| E5 | 时间切分 → 同窗口内随机 80/20 切分 | B 集 | 同上 | 随机切分虚高 → 证明时间切分必要 | AUC 0.7422（时间切分 0.6438），AP 0.4710、名额内精确 0.5900；随机切分把 AUC 抬高约 10 个百分点 |

两条基线（同一验证集、同一名额 356）：规则打分 AP 0.6412 / AUC 0.6510 / 名额内精确 0.7640 / Brier 0.4924；逻辑回归 B 集 AP 0.6498 / AUC 0.6438 / 名额内精确 0.7416 / Brier 0.2852。规则基线名额内精确率反而略高 8 人，但分数没校准（Brier 差一倍），取舍见 `docs/adr/0005-模型选择.md`。

## 7. 清洗规则（已落地，命中行数为本机库实测）

实现在 `src/bank/clean.py` 的 `run_checks()`，顺序固定为 R1→R7（顺序固定台账才可比）。**致命规则命中即中止构建**（`CleaningError`），非致命规则只登记台账，任何规则都不删行。台账写进 `data/frozen/manifest.json` 的 `cleaning` 段。

| 编号 | 规则 | 处理 | 命中行数 |
| --- | --- | --- | --- |
| R1 | `是否认购` 不是 `是` / `否` | 致命，中止 | 0 |
| R2 | `距上次联系天数` 为负但不等于 −1 | 致命，中止 | 0 |
| R3 | `距上次联系天数 != -1` 但 `上次营销结果 = 未知` | 记账，保留原值不修改 | **5** |
| R4 | `联系月份` 不在中文十二个月内 | 致命，中止 | 0 |
| R5 | `联系日期` 不在 1–31 | 致命，中止 | 0 |
| R6 | 原始 17 列出现真空值 | 致命，中止（「未知」是取值不是空值） | 0 |
| R7 | `通话时长 < 0` | 致命，中止（该列禁用，但仍须保证数据本身合法） | 0 |

控制台实证（`python -m bank.freeze`）：

```
清洗 7 条规则，命中 5 行（致命 0 行，记账 5 行）
  R3_pdays与上次结果冲突               命中     5 行  [记账]  距上次联系天数≠-1 但 上次营销结果=未知；保留原值，不修改
```

> 原则：**清洗只能报错或记账，不能悄悄删行**；行数从 45,211 → 21,093 的变化全部来自「窗口裁剪」这一条显式规则（`window` 段记录了起止日期），不是清洗悄悄删的。
